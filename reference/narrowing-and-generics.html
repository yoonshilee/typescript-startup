类型断言 value as Note 不是证据；它只是要求检查器相信你。外部 JSON 必须先作为 unknown 逐项验证。

判别联合与穷尽检查

type Result<T, E> =
  | { ok: true; value: T }
  | { ok: false; error: E };

function unwrap<T, E>(result: Result<T, E>): T {
  if (result.ok) {
    return result.value;
  }
  throw result.error;
}

每条路径通过 ok 获得不同字段。需要锁住全部分支时，把剩余值赋给 never；新增变体会在未处理位置产生诊断。

泛型：保留关系，不是把 any 换个字母

function first<T>(values: readonly T[]): T | undefined {
  return values[0];
}

const firstTag = first(["ts", "node"]); // string | undefined
const firstId = first([1, 2]);           // number | undefined

T 同时出现在输入元素和输出中，表达“输出与输入元素同类型”。如果类型参数只出现一次，通常不提供关系价值，直接使用具体类型或 unknown 可能更诚实。

约束与类型查询

条件与映射类型

type ElementOf<T> = T extends readonly (infer Item)[]
  ? Item
  : never;

type Optional<T> = {
  [Key in keyof T]?: T[Key];
};

条件类型在类型层根据可赋值关系选择；infer 从匹配结构中命名类型；映射类型遍历键。先用内置工具类型，只有多处真实关系无法直接表达时才自定义。

停止类型体操的信号

  • 类型错误比业务规则更难解释。
  • 调用者需要断言才能使用“安全”抽象。
  • 只为一个调用点建立多层条件类型。
  • 运行时边界仍未校验，却投入大量精力推导内部类型。
  • 一个直接对象类型或两个具名函数更短、更容易测试。
