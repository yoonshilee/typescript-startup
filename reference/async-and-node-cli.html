Promise 与 async/await

async function loadText(url: URL, signal: AbortSignal): Promise<string> {
  const response = await fetch(url, { signal });
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }
  return response.text();
}
  • async 函数总是返回 Promise；普通返回值会包装成 fulfilled Promise。
  • await 暂停当前 async 函数，不阻塞整个 Node 进程。
  • fetch 只有网络层失败/取消时拒绝；HTTP 404/500 需要检查 response.ok。
  • 外部 JSON 的静态类型是 unknown；解析成功不等于结构可信。

串行还是并发

关系写法含义
B 依赖 A 结果连续两次 await必须串行
A、B 独立且都必须成功Promise.all并发启动，任一失败则整体拒绝
需要每项成功/失败结果Promise.allSettled等待全部完成
只取最先成功Promise.any全部失败才拒绝

并发不是自动更好：文件写入顺序、速率限制、内存占用和取消语义都会改变选择。

失败与清理

try {
  await writeFile(temporaryPath, content, "utf8");
  await rename(temporaryPath, targetPath);
} catch (error: unknown) {
  throw new Error("Could not save notes.", { cause: error });
} finally {
  await rm(temporaryPath, { force: true });
}
  • catch 值按 unknown 处理；先检查再读取属性。
  • Error 的 cause 保留底层失败链，不把内部细节当公开 CLI 输出。
  • finally 用于无论成功失败都需要的清理。
  • 可恢复业务失败可用 Result<T, E> 建模；真正异常环境失败可抛 Error。
  • AbortSignal 需要沿调用链传递；捕获取消后不要伪装成普通成功。

文件持久化契约

type NoteFile = {
  version: 1;
  notes: Note[];
};
  1. 从可注入路径读取 UTF-8 文本。
  2. JSON.parse 后仍当 unknown 验证版本与每条记录。
  3. 写入同目录临时文件，确保内容完成后 rename 到目标。
  4. 损坏数据不静默覆盖；返回清楚、稳定的公开错误。
  5. 测试使用临时目录，不读写真实 data/notes.json。

原生测试清单

  • node:test 运行测试，node:assert/strict 做行为断言。
  • mkdtemp 创建隔离目录，测试结束后递归清理明确的临时路径。
  • 注入数据路径、时钟和网络边界，不修改真实用户文件。
  • 同时覆盖正常命令、空输入、未知 JSON、损坏文件、HTTP 失败、取消和退出码。
  • 原子写测试验证目标文件完整、临时文件被清理，而不依赖实现内部函数名。
