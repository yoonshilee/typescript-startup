ESM 最小模型

// src/model.ts
export type NoteId = string;
export function formatId(id: NoteId): string {
  return `note:${id}`;
}

// src/cli.ts
import { formatId } from "./model.ts";
import type { NoteId } from "./model.ts";
  • package.json 的 "type": "module" 把 .js 文件解释为 ESM。
  • 本课程源码导入写真实 .ts 扩展名，Node 24 可直接执行。
  • rewriteRelativeImportExtensions 在构建时把相对 .ts 改写为 .js。
  • import type 明确只存在于静态层，运行产物不发起该导入。
  • 模块边界应围绕职责，不为每个一行函数创建文件。

严格配置的意图

strict
启用严格类型检查家族，拒绝大量隐式不安全状态。
noUncheckedIndexedAccess
索引读取加入 undefined，贴近 JavaScript 越界现实。
exactOptionalPropertyTypes
区分属性缺失与属性存在但值为 undefined。
verbatimModuleSyntax
让导入导出按源码意图保留，类型导入显式书写。
erasableSyntaxOnly
限制为 Node 能通过删除类型直接执行的语法。
noUncheckedSideEffectImports
检查仅副作用导入是否能解析。

诊断顺序

  1. 确认当前 Node：node --version，必须符合 package engines。
  2. 确认依赖图：pnpm install --frozen-lockfile。
  3. 单独运行最窄命令，不从 pnpm check 的尾部错误猜原因。
  4. 模块找不到时检查导入扩展名、package type 与实际文件大小写。
  5. 编辑器与 CLI 结论冲突时，以仓库脚本输出为可复现证据。
  6. 构建成功但运行失败时，检查 dist 导入与运行时输入；类型已不在场。

Node 24 原生执行与构建

node src/cli.ts --help  # strip erasable types, then run
tsc --noEmit            # check only
tsc -p tsconfig.build.json # emit dist/*.js

三条命令不互相替代。开发阶段可直接运行获得短反馈；发布 bin 时使用普通 JavaScript 构建产物，减少目标机器对 TypeScript 运行支持的假设。
