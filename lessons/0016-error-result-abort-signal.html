失败要么沿异常通道传播，要么变成明确的数据

JavaScript 可以 throw 任意值，Promise rejection 也不保证是 Error；边界代码应先把 unknown 变成可用错误。Result 把预期失败放进可判别联合，AbortSignal 则传递取消请求与原因，但只有观察 signal 的操作才会真正停止。

本课代码文件：创建 src/lesson-16.ts，异步案例由 runner await；Lab 由课程 HTML 自动识别，无需特殊注释。

任务卡

完成物：实现泛型 captureLoadResult(load, signal)：预先检查取消，把 signal 传入 loader，并把成功或任意拒绝规范化为 LoadResult。

  • 理解 throw / rejection 可以携带任意 JavaScript 值。
  • 在 catch 中从 unknown 开始，用 instanceof Error 收窄。
  • 用 Error cause 保留底层失败，同时增加上下文。
  • 根据调用契约选择抛出异常或返回可判别 Result。
  • 用 AbortController、reason、throwIfAborted 与 abort 事件协作取消。

时间预算：模型与实验 65 分钟，Lab 25 分钟，复盘 10 分钟。

前置回忆：第 15 课的拒绝会沿 await 抛出

export async function demoAwaitedRejection(): Promise<string> {
  try {
    await Promise.reject(new Error("offline"));
    return "unreachable";
  } catch {
    return "caught";
  }
}

await 遇到 rejected Promise 时，在当前 async 函数的继续位置抛出 rejection reason。catch 能截获，但尚不知道捕获值是什么类型。

详细心智模型：保留原因、选择通道、协作取消

1. JavaScript 允许抛出任意值

export function demoThrownValues(): string[] {
  const values: unknown[] = [
    new Error("failed"),
    "failed",
    404,
  ];
  return values.map((value) => typeof value);
}

结果是 ["object", "string", "number"]。团队代码应优先 throw Error，但外部库、旧代码或 Promise 仍可能拒绝字符串、数字或对象，因此 catch 变量必须当作 unknown。

2. 先收窄，再读取 message

export function demoUnknownCatch(): string {
  try {
    throw "missing";
  } catch (error) {
    if (error instanceof Error) {
      return error.message;
    }
    return String(error);
  }
}

不能直接写 error.message；instanceof 只覆盖真实 Error，其余值用 String 得到稳定的人类可读消息。规范化不应假装知道不存在的 stack 或 code。

3. 一个小 helper 可以统一 unknown 错误边界

export function demoErrorNormalization(): string {
  function toError(value: unknown): Error {
    return value instanceof Error
      ? value
      : new Error(String(value));
  }

  return toError("offline").message;
}

真实 Error 保持同一对象，非 Error 才创建包装。Lab 使用同一规则，因此调用方总能安全读取 error.message，同时不会丢失已有 Error 的身份和 stack。

4. Error cause 为增加上下文保留原原因

export function demoErrorCause(): boolean {
  const original = new Error("ECONNREFUSED");
  const wrapped = new Error("Loading note failed", {
    cause: original,
  });
  return wrapped.cause === original;
}

cause 可以是任意值，不能盲目当成 Error。包装适合跨抽象层增加“正在做什么”；不要只复制 message 后丢掉原始原因。

5. finally 用于释放资源，不用于覆盖返回或异常

export function demoFinally(): string[] {
  const trace: string[] = [];
  try {
    trace.push("work");
  } finally {
    trace.push("cleanup");
  }
  return trace;
}

finally 无论成功或抛出都执行。不要在 finally 中 return 或 throw 新错误，它会覆盖原返回值或失败；第 22 课的原子文件写入会使用明确清理边界。

6. Result 把预期失败变成普通数据

export function demoResult(): (string | number)[] {
  type Result<T> =
    | { readonly ok: true; readonly value: T }
    | { readonly ok: false; readonly error: Error };

  function describe(result: Result<string>): string {
    if (!result.ok) {
      return result.error.message;
    }
    return result.value;
  }

  const success: Result<string> = { ok: true, value: "Draft" };
  const failure: Result<string> = { ok: false, error: new Error("missing") };
  const count: Result<number> = { ok: true, value: 42 };
  return [describe(success), describe(failure), count.value];
}

ok 是判别字段；true 分支有 value，false 分支有 error。Result 适合调用方预期并必须处理的失败。编程错误、不可恢复不变量破坏通常仍应抛出。

同一个 Result 定义覆盖成功、失败和数字结果，依次输出 "Draft"、"missing"、42。describe 的两个分支只读取各自允许的成员。

Result 迫使调用方检查 ok

不检查 ok 就不能安全读取 value 或 error。判别联合把遗漏失败分支变成编译器可见问题。

成功 Result 保留泛型值类型

Result<number> 的成功分支保持 number；Lab 的泛型 T 同样从 loader 穿过 capture 边界。

7. 异常与 Result 不应同时表达同一次预期失败

export async function demoCapturedFailure(): Promise<string> {
  async function capture(): Promise<{
    readonly ok: false;
    readonly error: Error;
  }> {
    try {
      throw new Error("offline");
    } catch (error) {
      return {
        ok: false,
        error: error instanceof Error
          ? error
          : new Error(String(error)),
      };
    }
  }

  const result = await capture();
  return result.error.message;
}

capture 已决定把 loader 失败转成数据，调用方不应还要 catch 同一个预期失败。反过来，若函数承诺拒绝，就不要再返回隐含的 undefined 表示失败。

8. AbortController 发出一次取消信号和原因

export function demoAbortReason(): boolean[] {
  const controller = new AbortController();
  const reason = new Error("cancelled");
  controller.abort(reason);

  return [
    controller.signal.aborted,
    controller.signal.reason === reason,
  ];
}

两个结果都是 true。abort 只触发一次；reason 可由调用方提供，未提供时通常是 AbortError DOMException。signal 是只读通知面，controller 是发出取消的能力。

9. 进入操作前先检查已取消 signal

export function demoThrowIfAborted(): string {
  const reason = new Error("already cancelled");
  const signal = AbortSignal.abort(reason);

  try {
    signal.throwIfAborted();
    return "unreachable";
  } catch (error) {
    return error === reason ? "same reason" : "other reason";
  }
}

throwIfAborted 会原样抛出 signal.reason。预检查能保证已取消调用不启动 loader；但它不能处理检查之后发生的取消。

10. 进行中的操作必须监听 signal 或传给支持 signal 的 API

export async function demoInFlightAbort(): Promise<string> {
  const controller = new AbortController();
  const pending = new Promise<string>((resolve, reject) => {
    controller.signal.addEventListener("abort", () => {
      reject(controller.signal.reason);
    }, { once: true });
    void resolve;
  });

  const reason = new Error("stopped");
  controller.abort(reason);
  try {
    return await pending;
  } catch (error) {
    return error === reason ? "stopped" : "other";
  }
}

监听器用 once 避免完成后继续保留。更常见的做法是把 signal 直接传给 fetch、文件 API 或自定义 loader，由拥有底层操作的一层负责停止。

11. AbortSignal.any 组合多个取消来源

export function demoCombinedSignal(): string {
  const manualReason = new Error("manual");
  const manual = AbortSignal.abort(manualReason);
  const timeout = new AbortController().signal;
  const combined = AbortSignal.any([timeout, manual]);

  return combined.reason === manualReason
    ? "manual"
    : "other";
}

任一输入取消都会取消组合 signal，并保留触发源的 reason。它适合“用户取消或超时任一发生”的边界；不要自己维护多个布尔标志。

12. 取消是请求，不是强制终止任意函数

export function demoIgnoredSignal(): boolean {
  const controller = new AbortController();
  const value = "completed";
  controller.abort();
  return value === "completed";
}

结果仍是 true，因为这段工作从未观察 signal。AbortSignal 不会杀线程、回滚副作用或中断同步表达式；API 必须明确接受并检查它。

失败所有权：底层产生 Error，中间层必要时用 cause 增加上下文，边界层选择继续抛出或转成 Result；取消 signal 始终传到真正拥有操作的一层。

export function demoDefaultAbort(): string {

常见误区

  1. 直接读取 catch 变量的 message。 捕获值可能不是 Error。
  2. 规范化时总创建新 Error。 这会丢失已有 Error 的身份和 stack。
  3. 只复制底层 message。 需要上下文时用 cause 保留原原因。
  4. 同时用 undefined、Result 和 throw 表示同一失败。 调用方无法知道该检查什么。
  5. 在 finally 中 return。 它会覆盖原结果或异常。
  6. 认为 controller.abort 会强制停止任意代码。 操作必须观察 signal。
  7. 只做开始前 aborted 检查。 进行中取消还需监听或下传 signal。
  8. 忽略 signal.reason。 它是定位取消来源的重要证据。
  9. 长期保留 abort listener。 使用 once 或在完成后移除。
  10. 把取消一律记录成系统故障。 用户取消、超时与真实失败可能需要不同呈现。

Lab 16：把可取消 loader 的完成状态变成 Result

由你创建或修改：创建 src/lesson-16.ts，把本课案例、改写和 Lab 都保存在这里。

不要修改：tests/lessons.test.ts 与 scripts/；它们是课程验收工具。

你要交付什么

type LoadResult<T> =
  | { readonly ok: true; readonly value: T }
  | { readonly ok: false; readonly error: Error };

type AbortableLoader<T> =
  (signal: AbortSignal) => Promise<T>;

captureLoadResult<T>(
  load: AbortableLoader<T>,
  signal: AbortSignal,
): Promise<LoadResult<T>>

运行规则

  1. 在调用 loader 前执行 signal.throwIfAborted()。
  2. 未取消时把同一个 signal 传给 loader，并 await 结果。
  3. 成功返回 { ok: true, value }。
  4. 失败若已是 Error，原样放入 error；否则用 new Error(String(error)) 包装。
  5. 不要重新 throw；预先取消、进行中取消和 loader 失败都返回 false 分支。

实现限制

  • 使用一个 try/catch、instanceof Error 和泛型 T。
  • 不要读取 message 来分类，不要使用 finally、Error cause、自定义 Error 子类、any、类型断言或非空断言。
  • 不要创建新的 AbortController，也不要替 loader 实现取消监听。
  • Lab 保持普通函数导出，由课程 HTML 自动识别。

capture 只拥有“转换完成状态”的责任；loader 拥有底层操作并决定怎样响应进行中取消。这保持了最小而诚实的边界。

提示 1 · try 包住哪些语句

把 throwIfAborted、loader 调用和 await 都放进同一个 try，才能统一处理预先取消和异步拒绝。

提示 2 · 成功分支保持 T

提示 3 · 只在必要时包装

catch 中使用三元表达式：error instanceof Error ? error : new Error(String(error))。

折叠完整答案与逐行解析

显示完整答案 
export type LoadResult<T> =
  | { readonly ok: true; readonly value: T }
  | { readonly ok: false; readonly error: Error };

export type AbortableLoader<T> =
  (signal: AbortSignal) => Promise<T>;

export async function captureLoadResult<T>(
  load: AbortableLoader<T>,
  signal: AbortSignal,
): Promise<LoadResult<T>> {
  try {
    signal.throwIfAborted();
    const value = await load(signal);
    return { ok: true, value };
  } catch (error) {
    return {
      ok: false,
      error: error instanceof Error
        ? error
        : new Error(String(error)),
    };
  }
}
第 1–4 行
LoadResult 用 ok 判别成功 T 与失败 Error，调用方必须处理对应字段。
第 6–7 行
AbortableLoader 明确底层操作接收 signal 并返回未来的 T。
第 9–12 行
泛型函数保持 loader 的结果类型，并公开 Promise<LoadResult<T>>。
第 13–16 行
try 同时覆盖预检查与 await；成功保留原 signal 和 value。
第 17–23 行
catch 从 unknown 收窄；真实 Error 原样保留，其余值才包装。
第 24–25 行
函数结束；没有重抛、隐藏取消或自建 controller。
