前置回忆：第 12 课的类型关系不会变成运行时对象

export function demoErasedAlias(): string {
  type EventName = `note:${string}`;
  const event: EventName = "note:add";

  return typeof event;
}

运行结果是 "string"，不是 "EventName"。type 别名只参与检查，不能传给 typeof、instanceof 或 console.log。Node 最终处理的是字符串值 event；这一课开始专门追踪这些运行时值和绑定。

详细心智模型：检查、擦除、执行、查找

1. 同一份 .ts 文件经历两个不同问题

  1. TypeScript 检查：参数、返回值、联合与泛型关系是否成立？
  2. 类型擦除或编译：类型标注和 type/import type 等静态语法不进入 JavaScript。
  3. Node 执行：值如何创建，函数以什么顺序调用，属性在哪里查找？
export function demoErasableSyntax(): string {
  function normalizeTitle(title: string): string {
    return title.trim();
  }

  return normalizeTitle(" Draft ");
}

Node 24 对可擦除 TypeScript 语法做轻量 type stripping，但不会替你做类型检查，也不会读取 tsconfig。课程因此把 pnpm typecheck 与 pnpm examples NN 分成两个明确命令。

2. typeof 只认识运行时类别

export function demoRuntimeTypes(): string[] {
  type NoteId = string;
  const id: NoteId = "n1";
  const tags = ["typescript"];
  const create = () => ({ id });

  return [typeof id, typeof tags, typeof create];
}

结果是 ["string", "object", "function"]。typeof 不知道 NoteId 或 string[]；数组在 JavaScript 中是对象，需要 Array.isArray 才能进一步判断。静态类型名在执行前已消失。

3. 词法作用域由源码嵌套位置决定

export function demoLexicalScope(): string[] {
  const status = "outer";
  const values = [status];

  {
    const status = "inner";
    values.push(status);
  }

  values.push(status);
  return values;
}

块内 status 遮蔽外层绑定，但没有改写它，所以结果是 ["outer", "inner", "outer"]。名称查找从当前位置向外层词法环境移动；它不根据“谁调用了函数”动态改变。

4. 每次同步函数调用都有独立局部绑定

export function demoCallOrder(): string[] {
  const trace: string[] = [];

  function normalizeTitle(title: string): string {
    trace.push("normalize:start");
    const normalized = title.trim();
    trace.push("normalize:end");
    return normalized;
  }

  function createTitle(title: string): string {
    trace.push("create:start");
    const normalized = normalizeTitle(title);
    trace.push("create:end");
    return normalized;
  }

  const title = createTitle(" Draft ");
  return [...trace, title];
}

同步顺序是 create:start、normalize:start、normalize:end、create:end、Draft。normalizeTitle 返回后，它的普通局部绑定可回收；createTitle 随后继续。Promise 与事件循环会在第 15 课加入，此处只有同步调用栈。

5. 闭包捕获外层绑定，因此能看到后续赋值

export function demoLiveClosureBinding(): string {
  let status = "draft";
  const readStatus = () => status;

  status = "published";
  return readStatus();
}

结果是 "published"。readStatus 不是保存 "draft" 的深拷贝，而是保留对外层 status 绑定的访问。调用发生时再读取当前值。

6. 外层调用结束后，被捕获的绑定仍可存活

export function demoCounters() {
  function createCounter(start: number): () => number {
    let current = start;
    return () => {
      current += 1;
      return current;
    };
  }

  const next = createCounter(10);
  const first = createCounter(0);
  const second = createCounter(0);
  return {
    sequence: [next(), next(), next()],
    independent: [first(), first(), second(), first(), second()],
  };
}

createCounter 已返回，但内部函数仍引用 current，所以结果中的 sequence 是 [11, 12, 13]。只要返回函数仍可达，它需要的词法环境就不能被回收。

每次外层调用创建一组独立绑定

independent 是 [1, 2, 1, 3, 2]。first 与 second 来自两次 createCounter 调用，各自捕获不同 current；它们没有共享全局计数器。

7. 闭包捕获对象绑定时，看到的是同一个对象引用

export function demoCapturedReference(): number[] {
  const settings = { limit: 10 };
  const readLimit = () => settings.limit;
  const before = readLimit();

  settings.limit = 20;
  return [before, readLimit()];
}

结果是 [10, 20]。闭包能通过 settings 绑定访问同一对象；修改属性不会替换绑定。这里与第 04 课的对象引用模型完全一致。

8. class 创建真实构造函数，方法位于 prototype

export function demoPrototype() {
  class Note {
    title: string;

    constructor(title: string) {
      this.title = title;
    }

    describe(): string {
      return this.title;
    }
  }

  type NoteShape = { title: string };
  const note = new Note("Draft");
  const first = note;
  const second = new Note("Release");
  const plain: NoteShape = { title: "Draft" };
  const instance: NoteShape = second;
  const copy = { ...note };
  return {
    lookup: [Object.hasOwn(note, "title"), Object.hasOwn(note, "describe"), note.describe()],
    shared: [first.describe === second.describe, Object.getPrototypeOf(first) === Note.prototype],
    instances: [plain instanceof Note, instance instanceof Note],
    spread: ["describe" in copy, copy instanceof Note],
  };
}

lookup 是 [true, false, "Draft"]：title 在构造时写入实例，是自有属性；describe 存在于 Note.prototype，沿原型链仍能找到并调用它。class 是原型机制上更清楚的语法，不是 Java 式静态类型容器。

同一个 Note 类依次检查 lookup、shared、instances、spread 四组结果。各组含义在下方分开解释，类只需写一次。

同一 class 的实例共享原型方法函数

shared 的两项都是 true。每个实例有自己的 title，但 describe 函数只存一份在共享原型上。读取 first.describe 时，运行时先检查实例，再沿 [[Prototype]] 找到 Note.prototype.describe。

结构类型相同，不代表运行时 instanceof 相同

两个值都满足 NoteShape，但 instances 是 [false, true]。TypeScript 的结构赋值关系已擦除；instanceof 检查的是 Note.prototype 是否出现在对象的运行时原型链中。

对象展开不会保留 class 原型

spread 的两项都是 false。展开只复制自有可枚举属性 title，不复制 [[Prototype]]；因此第 11 课的更新函数明确只面向普通数据对象。

9. 从对象上拆下依赖 this 的方法会失去接收者

function demoDetachedMethod(): string {
  class Note {
    title = "Draft";

    describe(): string {
      return this.title;
    }
  }

  const note = new Note();
  const describe = note.describe;
  return describe();
}

模块以严格模式执行，独立调用 describe 时 this 是 undefined，因此该案例会抛错。它保持非导出，不会被自动 runner 执行；危险行为仍可见，而不是藏进正常案例。

10. bind 显式创建固定接收者的新函数

export function demoBoundMethod(): string {
  class Note {
    title = "Draft";

    describe(): string {
      return this.title;
    }
  }

  const note = new Note();
  const describe = note.describe.bind(note);
  return describe();
}

bind 返回一个新函数，把之后调用时的 this 固定为 note。若不需要动态接收者，闭包 () => note.describe() 也能清楚表达同一意图。

执行边界：类型不会捕获状态、创建原型或修复 this；这些行为都来自 JavaScript 值、函数创建位置、调用方式和对象链。

补充观察与运行

示例 A：for 循环中的 let 为每轮创建独立绑定

export function demoLoopClosureBindings(): number[] {
  const readers: Array<() => number> = [];

  for (let index = 0; index < 3; index += 1) {
    readers.push(() => index);
  }

  return readers.map((read) => read());
}

结果是 [0, 1, 2]。let 在每次迭代提供新的 index 绑定，每个闭包引用对应一轮；这不同于旧代码中函数作用域 var 让所有闭包共享一个最终绑定。

示例 B：Lab 所需的状态属于每个工厂闭包

export function demoFactoryState(): string[] {
  function createFactory(prefix: string): (title: string) => string {
    let nextId = 1;
    return (title) => `${prefix}-${nextId++}:${title}`;
  }

  const createCourse = createFactory("course");
  const createWork = createFactory("work");
  return [
    createCourse("Draft"),
    createCourse("Release"),
    createWork("Plan"),
  ];
}

结果是 course-1:Draft、course-2:Release、work-1:Plan。prefix 与 nextId 都由各自闭包保存；不需要全局变量或工厂类。

常见误区

  1. 用 Node 执行成功代替类型检查。 type stripping 不会报告类型错误。
  2. 认为 type 或 interface 可以被 typeof 检查。 它们没有运行时值。
  3. 把词法作用域理解为调用者作用域。 名称查找取决于函数定义位置。
  4. 认为闭包保存变量当时的值副本。 它保留对绑定的访问，能看到后续赋值。
  5. 把两次工厂调用误认为共享同一局部状态。 每个调用创建独立词法环境。
  6. 认为类型只读会冻结闭包中的对象。 readonly 不改变运行时引用或属性。
  7. 认为 class 方法复制到每个实例。 普通方法位于共享 prototype。
  8. 把结构可赋值等同于 instanceof。 instanceof 只检查运行时原型链。
  9. 随手拆下使用 this 的方法。 独立调用会失去原接收者。
  10. 用对象展开克隆 class 实例。 展开不会复制原型和非枚举成员。

Lab 13：创建拥有独立序号状态的笔记工厂

由你创建或修改：创建 src/lesson-13.ts，把本课案例、改写和 Lab 都保存在这里。

你要交付什么

导出一个结果类型和工厂函数：

type CreatedNote = {
  readonly id: string;
  title: string;
};

createNoteFactory(
  prefix: string,
): (title: string) => CreatedNote

运行规则

  1. 每次 createNoteFactory 调用创建自己的 nextId，初始值为 1。
  2. 返回函数每次创建一个新对象，id 为 prefix-nextId，title 原样保留。
  3. 创建对象后把该闭包的 nextId 增加 1。
  4. 同一工厂连续得到 1、2、3；另一个工厂从自己的 1 开始。

类型与实现限制

  • prefix 与 title 都必须是 string，结果 id 对调用方只读。
  • 不要 trim、转换大小写或修改 prefix/title。
  • 不要使用全局变量、class、静态属性、数组历史、Map、any、unknown 或类型断言。
  • Lab 保持普通函数导出，由课程 HTML 自动识别。

一个闭包和一个数字绑定已经满足需求。第 14 课会把这个工厂放进真实 ESM 模块，并解释导入时模块如何被解析与复用。

三层提示

提示 1 · 状态写在哪里

在 createNoteFactory 函数体内、返回函数外声明 let nextId = 1。这样每次工厂调用得到独立绑定。

提示 2 · 先创建对象，再更新序号

返回函数先用当前 nextId 创建 note，再执行 nextId += 1，最后返回 note；顺序能避免第一个 id 从 2 开始。

提示 3 · 字符串与对象都无需额外工具

id 用模板字符串 `${prefix}-${nextId}`，结果用普通对象字面量 { id, title }。

折叠完整答案与逐行解析

显示完整答案 
export type CreatedNote = {
  readonly id: string;
  title: string;
};

export function createNoteFactory(
  prefix: string,
): (title: string) => CreatedNote {
  let nextId = 1;

  return (title) => {
    const note = {
      id: `${prefix}-${nextId}`,
      title,
    };
    nextId += 1;
    return note;
  };
}
第 1–4 行
CreatedNote 描述返回数据；readonly id 是静态写入限制，不会冻结对象。
第 6–8 行
工厂接收 prefix，并返回接收 title 的函数；两层签名对应两个调用阶段。
第 9 行
每次外层调用创建独立 nextId 绑定，初始值为 1。
第 11–15 行
返回闭包读取 prefix 与当前 nextId，创建新的普通对象并原样保存 title。
第 16–17 行
只更新当前闭包的 nextId，再返回新对象；另一工厂的状态不受影响。
第 18–19 行
内外函数结束；没有全局状态、类、集合或类型断言。
