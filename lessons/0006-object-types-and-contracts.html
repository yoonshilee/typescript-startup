对象契约描述需要的形状，不要求共同的类身份

TypeScript 主要比较对象拥有哪些成员，而不是它由哪个类创建。你将从内联对象类型开始，用 type 与 interface 命名形状，并准确处理可选、只读与 satisfies 的静态边界。

前置回忆：对象已有运行时形状，类型为它建立静态契约

第 04 课创建过普通 JavaScript 对象，第 05 课观察过对象属性的推断。即使不写接口，运行时对象也已经有属性：

export function createInferredNote() {
  return {
    id: "n1",
    title: "TypeScript",
  };
}

TypeScript 会推断返回值包含 id: string 与 title: string。本课新增的对象类型不是创建另一份对象，而是给多个参数、变量和返回值复用同一个形状契约。

详细心智模型：从匿名形状到可复用对象契约

1. 内联对象类型逐项检查属性

对象类型写在参数位置时，花括号内不是运行时对象，而是静态成员清单：

export function demoInlineNote(): string {
  function formatInlineNote(note: { id: string; title: string }): string {
    return `${note.id}:${note.title}`;
  }

  return formatInlineNote({ id: "n1", title: "TypeScript" });
}
  1. note 是参数名。
  2. { id: string; title: string } 是参数必须满足的对象形状。
  3. id 与 title 都是必需属性，值都必须是字符串。
  4. 分号只分隔类型成员；运行时对象仍使用逗号分隔属性值。

少一个必需属性或属性值类型不匹配都会报错。这个写法适合只出现一次的短形状；重复时应命名，避免多个位置慢慢漂移。

2. type 给类型表达式起名字

type NoteHeading = {
  title: string;
  body?: string;
};

export function demoHeading(): string[] {
  function formatHeading(note: NoteHeading): string {
    return note.body ? `${note.title}: ${note.body}` : note.title;
  }

  const titleOnly: NoteHeading = { title: "Draft" };
  const complete: NoteHeading = { title: "Release", body: "Ship it" };

  return [formatHeading(titleOnly), formatHeading(complete)];
}

type NoteHeading = ... 创建的是类型别名，不是变量，也不会出现在运行时。这里复用了一个对象形状；后续课程还会看到 type 命名其他类型表达式。

可选属性表示“可以不存在”

body?: string 中的问号属于属性名。上面同一个 formatHeading 接收两种输入：titleOnly 省略 body，complete 提供字符串 body；结果依次是 Draft 和 Release: Ship it。

本项目启用了 exactOptionalPropertyTypes，因此“没有 body”与“显式写 body: undefined”不是同一个契约。读取可选属性时必须承认它可能不存在；完整的 undefined 边界会在第 08 课系统展开。

3. interface 直接声明对象契约

interface NotePreview {
  readonly id: string;
  title: string;
  body?: string;
}

export function demoPreviewTitle(): string {
  function readPreviewTitle(note: NotePreview): string {
    return note.title;
  }

  return readPreviewTitle({ id: "n2", title: "Preview" });
}

在这个简单对象例子里，type 与 interface 都能工作。不要把选择变成风格战争：遵循仓库现有约定即可。本课程用 interface 表达主要领域对象，用 type 表达组合与其他类型关系。

4. 固定同一形状后，二者的对象检查相同

type NoteByType = {
  title: string;
  body?: string;
};

interface NoteByInterface {
  title: string;
  body?: string;
}

export function compareObjectTypes() {
  const byType: NoteByType = { title: "Draft" };
  const byInterface: NoteByInterface = byType;
  const roundTrip: NoteByType = byInterface;

  return {
    sameReference: byType === byInterface,
    titles: [byType.title, roundTrip.title],
  };
}
  1. byType 创建一个普通运行时对象；NoteByType 不会创建包装值。
  2. 赋给 byInterface 时，编译器只比较 title 与 body 的结构；不要求两个类型名称相同。
  3. 赋值复制的是同一个对象引用，因此 sameReference 是 true；两种类型声明都不会转换或克隆对象。
  4. 反向赋给 roundTrip 也成立，因为两个静态形状相同。输出 JavaScript 后，两个类型名称都会消失。

type 可以命名对象之外的类型表达式

下一课预览：下面的竖线表示“候选之一”，这里只用于看清 type 的表达范围，不进入本课 Lab；联合类型与收窄会在第 07 课展开。
export function demoTypeAliasRange(): string {
  type NoteId = string | number;
  type NoteStatus = "draft" | "published";

  const id: NoteId = "n1";
  const status: NoteStatus = "draft";
  return `${typeof id}:${status}`;
}

type 可以给对象、基本类型别名、联合、元组、函数类型以及后续的映射类型和条件类型命名。interface 主要声明对象成员契约，不能直接替代 type NoteId = string | number。

interface 的同名声明会合并

interface MergedNote {
  title: string;
}

interface MergedNote {
  body?: string;
}

export function demoInterfaceMerging(): string {
  const note: MergedNote = {
    title: "Draft",
    body: "Keep",
  };
  return `${note.title}:${note.body ?? "No body"}`;
}

type ClosedNote = { title: string };
// type ClosedNote = { body?: string }; // 类型错误：名称重复。

编译器把两份 MergedNote 合成同时拥有 title 与可选 body 的一个接口；同名 type 则直接报错。声明合并常用于扩充第三方库或全局契约，普通应用代码不应为了拆文件而滥用它。

需求选择原因
命名普通对象形状type 或 interface结构检查基本相同，遵循项目约定
命名联合或其他类型表达式typeinterface 不能直接表示这些结果
有意允许同名声明扩充interface接口支持声明合并
本课程主要领域对象interface这是课程的一致性约定，不是运行时要求

5. readonly 阻止通过该类型位置重新赋值

readonly id: string 允许创建时提供 id，之后禁止通过 NotePreview 位置改写它。其他未标记属性仍可修改：

export function demoPreviewRename(): NotePreview {
  function renamePreview(note: NotePreview, title: string): NotePreview {
    note.title = title;
    // note.id = "other"; // 类型错误：id 是 readonly。
    return note;
  }

  return renamePreview({ id: "n3", title: "Old" }, "New");
}

readonly 不会调用 Object.freeze()，也不是深度不可变。它只限制当前属性写入；若属性保存数组引用，数组内容是否可改还由数组自己的类型决定。

6. 结构类型只关心所需成员

interface TitledValue {
  title: string;
}

export function demoStructuralMatch(): string {
  function readStructuralTitle(value: TitledValue): string {
    return value.title;
  }

  const detailedNote = {
    id: "n1",
    title: "Release",
    body: "Ship it",
  };

  return readStructuralTitle(detailedNote);
}

detailedNote 没有声明 implements TitledValue，但它拥有兼容的 title: string，所以可以传入。Java 通常要求名义上的类或接口关系；TypeScript 主要按成员结构比较。

新对象字面量会额外检查未知属性：直接调用 readStructuralTitle({ title: "Release", typo: true }) 会报告多余属性，帮助发现拼写错误；先保存到变量后再传入时，结构兼容允许额外成员。不要用类型断言绕过真正的 typo。

7. satisfies 检查形状，同时保留原表达式类型

显式标注会把变量视为标注类型；satisfies 则检查右侧表达式能否赋给目标类型，但结果仍保留右侧自身的推断：

interface ListSettings {
  readonly status: string;
  readonly limit: number;
}

export function createCheckedSettings() {
  const settings = {
    status: "active",
    limit: 20,
  } as const satisfies ListSettings;

  return settings;
}

as const 负责保留 "active" 与 20 并产生只读属性；satisfies ListSettings 负责检查属性名和值类型。两者都只影响静态检查，不执行运行时校验或转换。

若把 status 拼错为 stats，或把 limit 写成字符串，satisfies 会在对象创建处报错。它适合配置对象与固定映射；普通函数参数已有明确类型时，不需要每个对象都追加它。

本课选择：短且只用一次的形状可以内联；复用对象契约用仓库已有的 interface 或 type 风格；可选与只读必须表达真实领域语义；satisfies 只在需要“检查但保留推断”时使用。

最容易从 Java 带来的误解，是把 TypeScript interface 当成必须显式实现的名义关系。最容易从 Python 带来的误解，是把静态对象类型当成运行时 schema；TypeScript 默认不会验证 JSON 或用户输入。

补充观察与运行

示例 A：函数只要求自己真正使用的属性

type HasTitle = {
  title: string;
};

export function demoUppercaseTitle(): string {
  function uppercaseTitle(value: HasTitle): string {
    return value.title.toUpperCase();
  }

  return uppercaseTitle({ title: "TypeScript" });
}

函数不读取 id、body 或状态，就不应把这些属性塞进参数契约。更小的真实要求让函数更容易复用。

示例 B：可选属性需要分支后才能按字符串使用

interface DescribedNote {
  title: string;
  body?: string;
}

export function demoBodySummary(): string {
  function summarizeBody(note: DescribedNote): string {
    if (!note.body) {
      return "No body";
    }

    return note.body.trim();
  }

  return summarizeBody({ title: "Draft" });
}

条件为假时提前返回，后面的 note.body 才能安全调用字符串方法。这个分支复用了第 02–03 课的 truthiness 与控制流。

示例 C：返回新对象可以保留只读标识

interface RenameableNote {
  readonly id: string;
  title: string;
}

export function demoRenamedNote(): RenameableNote {
  function renamedNote(note: RenameableNote, title: string): RenameableNote {
    return {
      ...note,
      title,
    };
  }

  return renamedNote({ id: "n2", title: "Old" }, "New");
}

没有给 note.id 重新赋值；对象展开读取旧 id，再创建新对象。readonly 限制写入位置，不妨碍复制其值。

示例 D：satisfies 在错误发生处检查配置

interface SearchDefaults {
  readonly query: string;
  readonly limit: number;
}

export function buildSearchDefaults() {
  return {
    query: "",
    limit: 20,
  } as const satisfies SearchDefaults;
}

若配置漏掉 limit 或把它写成字符串，错误会出现在返回对象旁边。结果仍保留 query: "" 与 limit: 20 的精确推断。

常见误区

  1. 把 interface 当成 Java 接口身份。 普通对象只要成员兼容就能满足它，无需显式 implements。
  2. 认为 type 与 interface 在所有位置都能互换。 普通对象形状相近，但联合等类型表达式需要 type，同名声明合并则属于 interface。
  3. 认为 body?: string 等于必须存在的 body: undefined。 本项目把缺少属性与显式 undefined 区分开。
  4. 把 readonly 当深度冻结。 它只阻止当前属性写入，不生成运行时代码。
  5. 同时维护多份相同内联对象类型。 重复形状会漂移；真正复用时命名一次。
  6. 把所有对象都写成巨大领域接口。 参数只声明函数真正需要的最小成员。
  7. 用 satisfies 代替运行时校验。 外部输入仍可能是任意错误数据。

Learning Contract

进入联合类型与收窄前，你应当能够：

  • 逐项解释内联对象类型中的属性名、必需性、只读性和值类型。
  • 说明相同对象形状使用 type 或 interface 时为何能够相互赋值且不会转换运行时对象。
  • 指出 type 可以命名联合等类型表达式，而 interface 可以进行声明合并。
  • 预测缺少属性、错误属性类型、额外属性和结构兼容的检查结果。
  • 正确处理可选属性读取，并解释本项目的 exact optional 语义。
  • 说明 readonly、as const、satisfies 与运行时冻结各自负责什么。

你要交付什么

DraftNote 的精确契约

属性要求含义
idreadonly id: string创建时必需，之后不能通过 DraftNote 改写
titletitle: string必需，可在新对象中替换为规范化标题
bodybody?: string可以不存在；存在时必须是字符串

一次调用的明确结果

阶段值
输入{ id: "n1", title: " Draft ", body: "Keep" }
返回{ id: "n1", title: "Draft", body: "Keep" }
调用后输入仍为原内容，且返回值不是同一对象

normalizeDraft 必须按什么规则工作

  1. 参数标注为 DraftNote。
  2. 创建新对象并复制输入的全部现有属性，不修改输入对象。
  3. 只把 title 替换为 note.title.trim()；id 与可选 body 原样保留。
  4. 在返回对象后写 satisfies DraftNote，由编译器检查形状。

完成条件

  • 带 body 和不带 body 的输入都能通过，并保持 body 的“存在/缺少”状态。
  • 返回标题去除首尾空白；其他值不变。
  • 返回新对象，输入对象的身份和内容保持不变。
  • 缺少必需属性、错误属性类型和改写 readonly id 都会被类型检查拒绝。

三层提示

提示 1 · 先准确声明三个属性

用 export interface DraftNote 开始。id 前写 readonly，body 名称后写 ?，三个值类型都是 string。

提示 2 · 复制后覆盖标题

返回对象先写 ...note，再写 title: note.title.trim()。后写的同名属性覆盖旧标题，其他现有属性保持不变。

提示 3 · 检查形状但保留推断

在返回对象的右花括号后写 satisfies DraftNote。函数无需再写显式返回类型。

折叠完整答案与逐行解析

显示完整答案 
export interface DraftNote {
  readonly id: string;
  title: string;
  body?: string;
}

export function normalizeDraft(note: DraftNote) {
  return {
    ...note,
    title: note.title.trim(),
  } satisfies DraftNote;
}
第 1–5 行
导出对象契约：id 必需且只读，title 必需可写，body 可以缺少但存在时必须是字符串。
第 7 行
函数参数必须满足 DraftNote；返回类型留给编译器从返回表达式推断。
第 8–11 行
对象展开创建新对象并保留现有属性，后写的 title 用 trim 结果覆盖旧标题；satisfies 在此处检查结果满足 DraftNote。
第 12 行
函数结束。整个过程没有修改输入，也没有生成任何运行时类型对象。
