文件边界既是名称边界，也是运行时加载边界

ESM 用静态 import/export 连接模块；Node 根据 specifier、文件扩展名与最近的 package.json 决定怎样加载；TypeScript 必须模仿这个 host，同时把纯类型导入从输出中擦除。

前置回忆：第 13 课的每个模块仍运行普通 JavaScript

export function demoModuleScope(): string {
  const label = "lesson-14";
  return label;
}

出现 export 后，文件是模块，顶层绑定属于该模块而不是全局对象。导入者只能访问明确导出的名称；未导出的 label 仍可供模块内函数使用。

详细心智模型：specifier 交给 host，类型关系交给编译器

1. 先把本课的值导入与类型导入放在文件顶部

import { basename } from "node:path";
import type { PathLike } from "node:fs";

basename 是运行时函数，生成的 JavaScript 必须保留第一条 import。PathLike 只描述参数类型，第二条 import 会完整擦除。项目启用了 verbatimModuleSyntax，因此是否写 type 直接决定语句是否保留。

2. ESM 给每个文件独立作用域和明确公开表面

const MODULE_LABEL = "lesson-14";

export function demoPrivateBinding(): string {
  return MODULE_LABEL;
}

MODULE_LABEL 是模块私有绑定；函数是命名导出。导入者不能按名字访问 MODULE_LABEL，也不会因为多个文件都写了同名 const 而冲突。

3. export 输出绑定，import 在另一模块建立只读连接

// note-store.ts
export let noteCount = 0;

export function addNote(): void {
  noteCount += 1;
}

// cli.ts
import { addNote, noteCount } from "./note-store.ts";

addNote();
console.log(noteCount); // 1

命名 import 不是在导入时复制 noteCount 的数字；它连接导出模块中的 live binding，所以 addNote 更新后能读到 1。导入者不能直接给 noteCount 重新赋值。

4. import type 明确“只检查，不加载值”

export function demoTypeOnlyImport(): string {
  function describePath(path: PathLike): string {
    return typeof path;
  }

  return describePath("notes.json");
}

PathLike 只出现在类型位置，运行时函数只接收字符串并返回 "string"。若被导入模块有顶层副作用，import type 不会为了这个类型去执行模块。

5. export type 同样不会产生运行时导出

export type ModuleDescriptor = {
  readonly label: string;
  readonly format: "esm";
};

export function demoTypeExport(): string {
  const descriptor: ModuleDescriptor = {
    label: "lesson-14",
    format: "esm",
  };
  return descriptor.format;
}

其他文件可以 import type { ModuleDescriptor }，但动态查看模块 namespace 时不会出现 ModuleDescriptor。只有 demoTypeExport 这样的值导出进入运行时导出表。

6. package.json 决定 .js 文件位于哪种包语义

{
  "type": "module"
}

本项目最近的 package.json 写明 type=module，因此普通 .js 输出按 ESM 解释；.mjs 始终是 ESM，.cjs 始终是 CommonJS。不要仅凭源文件看起来像 import/export 就猜运行时格式。

7. specifier 的类别决定由谁解析

形式示例Node 的起点
node: 内置node:pathNode 内置模块表
相对路径./note-store.ts当前模块 URL

TypeScript 不是运行时 host；它根据 module/moduleResolution 设置模仿 Node，以便提前发现最终 import 无法加载或类型不匹配的问题。

8. Node ESM 的相对 specifier 必须写扩展名

// Direct Node 24 source execution:
import { addNote } from "./note-store.ts";

// tsconfig.build.json rewrites emitted relative extensions:
import { addNote } from "./note-store.js";

课程源码直接由 Node 24 执行，所以相对 TypeScript specifier 写 .ts。构建时 rewriteRelativeImportExtensions 把相对 .ts 改成 .js；Node 运行 dist 时就能找到实际产物。省略扩展名不是 Node ESM 的目录猜测规则。

9. node: specifier 明确这是内置运行时依赖

export function demoBuiltinImport(): string {
  return basename("/workspace/notes.json");
}

结果是 "notes.json"。node:path 不走项目的 node_modules，也不会与同名第三方包混淆；basename 是真实值导入，所以会保留在运行时代码里。

10. ESM 使用 import.meta.url 表示当前模块位置

export function demoImportMeta() {
  const currentModule = new URL(import.meta.url);
  const resource = new URL("./notes.json", currentModule);
  return { moduleProtocol: currentModule.protocol, resourceProtocol: resource.protocol };
}

moduleProtocol 在本地模块中是 "file:"。ESM 没有 CommonJS 注入的 __filename 与 __dirname；需要路径时先从 import.meta.url 得到 URL，再按具体 API 要求保留 URL 或转换文件路径。

URL 可以安全解析相对模块资源

resourceProtocol 同样是 "file:"。URL 构造以当前模块为基准解析资源位置，不用字符串拼接当前目录；第 18 课会进一步学习 fileURLToPath 与文件 API。

11. 同一规范化 URL 只链接和评估一次

let evaluationCount = 0;
evaluationCount += 1;

export function demoSingleEvaluation(): number {
  return evaluationCount;
}

同一进程再次 import 同一 URL 会复用已存在的 module record，所以函数持续返回 1，不会重跑顶层加法。不同 query 或 fragment 会形成不同 URL，可能得到独立模块实例。

12. 模块级状态由该模块实例共享

let exampleNextId = 1;

export function demoModuleState(): string[] {
  function createId(): string {
    const id = `example-${exampleNextId}`;
    exampleNextId += 1;
    return id;
  }

  return [createId(), createId()];
}

同一模块实例中的导出函数共享 exampleNextId。它不同于第 13 课“每次工厂调用一份闭包状态”：模块状态只有一份，因此必须有清楚的所有权、测试隔离和重置策略。Lab 刻意用它观察缓存，不把它推广成默认设计。

13. 循环依赖先建立连接，再按依赖图评估

// a.ts
import { bValue } from "./b.ts";
export const aValue = `a:${bValue}`;

// b.ts
import { aValue } from "./a.ts";
export const bValue = `b:${aValue}`;

两个模块的导入绑定会先链接，但读取尚未完成初始化的 const 可能触发 ReferenceError。不要靠调整 import 顺序猜测修复；更小、更单向的依赖图，或把共享契约移到第三个无副作用模块，通常更清楚。

14. 课程优先命名导出，让调用点保持可搜索

export function demoNamedExport(): string {
  return "named";
}

默认导出允许导入者任意重命名，适合确有单一主要值的模块；本课程的案例和 Lab 使用命名导出，使函数名、自动发现输出和测试契约一致。这里不为风格偏好创建额外包装模块。

解析顺序：先确定 host 与模块格式，再分类 specifier、解析目标 URL、链接导入导出，最后按依赖顺序评估一次。类型导入在运行时链路开始前已经擦除。

补充观察与运行

示例 A：相同文件加不同 query 会成为不同 URL

export function demoUrlIdentity(): boolean {
  const base = new URL(import.meta.url);
  const first = new URL(base);
  const second = new URL(base);
  second.searchParams.set("version", "2");
  return first.href === second.href;
}

结果是 false。Node 按 URL 缓存 ESM；不要随意给本地 import 添加 query 来“刷新模块”，那会制造第二份模块状态。

常见误区

  1. 认为 import 只是把文件文本粘贴进来。 ESM 先解析、链接，再按图评估模块。
  2. 用普通 import 引入纯类型。 verbatimModuleSyntax 下应明确写 import type。
  3. 认为 export type 会出现在模块 namespace。 它在输出前擦除。
  4. 省略相对路径扩展名。 Node ESM 要求完整 specifier。
  5. 源码写 .js 却又期待 Node 直接找到 .ts。 本项目源码直跑与构建产物由 rewrite 连接。
  6. 在 ESM 中直接使用 require、__filename 或 __dirname。 它们不是 ESM 注入绑定。
  7. 认为同一文件路径每次 import 都重新执行。 同一 URL 通常复用模块实例。
  8. 忽略 query/fragment 对缓存身份的影响。 不同 URL 可产生不同实例。
  9. 用循环 import 顺序解决初始化错误。 应重画依赖方向或提取共享模块。
  10. 把模块顶层副作用当作普通声明。 第一次评估会真实执行它。

Learning Contract

进入 Promise、async/await 与事件循环前，你应当能够：

  • 画出两个 ESM 文件的导入、导出和私有绑定边界。
  • 区分值 import/export 与 type-only import/export 的输出。
  • 根据 package.json type、扩展名和 NodeNext 判断模块格式。
  • 把 node:、相对、包与 file: URL specifier 分到正确解析入口。
  • 解释源码 .ts 扩展名如何由 build rewrite 成 .js。
  • 使用 import.meta.url 而不是假设 CommonJS 目录变量存在。
  • 解释 live binding、单次评估与按 URL 缓存。
  • 识别循环依赖与顶层副作用的初始化风险。

Lab 14：观察模块缓存与模块私有状态

由你创建或修改：创建 src/lesson-14.ts，把本课 import、案例、改写和 Lab 都保存在这里。

不要修改：tests/lessons.test.ts 与 scripts/；它们是课程验收工具。

你要交付什么

导出一个类型和命名函数；序号绑定保持模块私有：

type ModuleNote = {
  readonly id: string;
  title: string;
};

createModuleNote(title: string): ModuleNote

运行规则

  1. 在模块顶层声明私有 let nextModuleId = 1，不要导出。
  2. 每次调用返回新对象，id 为 module-nextModuleId，title 原样保留。
  3. 返回前后都可以更新计数，但第一个结果必须是 module-1，随后是 module-2、module-3。
  4. 测试会再次 import 完全相同的模块 URL；模块不得重置序号。

类型与实现限制

  • 使用命名 export；ModuleNote 只导出类型，createModuleNote 导出运行时值。
  • 不要 trim 或修改 title，不要导出 nextModuleId。
  • 不要使用 globalThis、process、class、闭包工厂、数组历史、Map、any、unknown 或类型断言。
  • Lab 保持普通函数导出，由课程 HTML 自动识别。

模块顶层状态只为观察单次评估与缓存；真实持久化会在第 18/22 课交给文件与明确存储边界，而不是依赖进程内计数。

保存 src/lesson-14.ts 后，点击下方“校验练习”查看通过或失败结果；这与 pnpm lesson 14 使用同一套运行时与类型契约测试，不会执行折叠答案。

三层提示

提示 1 · 模块私有绑定写在哪里

把 let nextModuleId = 1 写在函数外，但不要加 export。整个模块实例中的函数都能读取它。

提示 2 · 类型和值使用不同 export

ModuleNote 写 export type；函数写普通 export function，无需添加额外注释。

提示 3 · 最小运行时实现

用当前数字创建 `module-${nextModuleId}`，递增绑定，再返回 { id, title }。

折叠完整答案与逐行解析

显示完整答案 
let nextModuleId = 1;

export type ModuleNote = {
  readonly id: string;
  title: string;
};

export function createModuleNote(title: string): ModuleNote {
  const note = {
    id: `module-${nextModuleId}`,
    title,
  };
  nextModuleId += 1;
  return note;
}
第 1 行
nextModuleId 属于模块实例，不导出；同一 URL 的重复 import 复用这个绑定。
第 3–6 行
ModuleNote 是纯类型导出，生成 JavaScript 时完全擦除；readonly 只限制调用方写 id。
第 8 行
createModuleNote 是命名值导出，导入者拿到指向该模块函数绑定的连接。
第 9–12 行
用当前模块序号创建新对象并原样保留 title。
第 13–14 行
更新模块私有绑定后返回；再次导入同一 URL 不会重跑第 1 行。
第 15 行
函数结束；没有全局对象、工厂类或导出的可变状态。
