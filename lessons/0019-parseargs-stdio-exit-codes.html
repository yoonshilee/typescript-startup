详细心智模型：进程字符串 → 语法 → 命令

第 07 课用七种命令练习联合与穷尽检查；这里先把可执行范围收敛为 add、list、help，供第 24 课编排。两课的命令类型服务于不同阶段，不要直接拿第 07 课的类型替代这里的协议；其余命令可以在完成这条最小链后扩展。

1. process.argv 前两项不属于业务参数

export function demoArgvSlice(): string[] {
  const argv = ["/usr/bin/node", "/app/dist/cli.js", "list"];
  return argv.slice(2);
}

入口通常调用 parseNoteCommand(process.argv.slice(2))。测试直接传用户参数，因此不依赖机器上的 Node 路径。

2. parseArgs 拆分 options 与 positionals

import { parseArgs } from "node:util";

export function demoParsedOptions() {
  function parse(args: string[]) {
    return parseArgs({
      args,
      options: { json: { type: "boolean", short: "j" } },
      allowPositionals: true,
      strict: true,
    });
  }

  return { long: parse(["list", "--json"]), short: parse(["list", "-j"]) };
}

标准库负责 --json 的词法规则与未知选项错误；应用仍要判断 list 能否带额外位置参数。

短选项映射

选项定义是唯一映射；业务只读取 json。

3. 可判别联合是命令协议

export function demoCommandUnion(): string {
  type Command =
    | { kind: "add"; title: string }
    | { kind: "list"; json: boolean }
    | { kind: "help" };
  const command: Command = { kind: "list", json: false };
  return command.kind;
}

解析完成后，kind 驱动穷尽分支。业务代码不再读取 positionals[0] 或猜某个布尔选项是否有效。

4. stdout 是成功数据，stderr 是诊断

export function demoProcessResult() {
  return [
    { exitCode: 0, stdout: "n1\tDraft\n", stderr: "" },
    { exitCode: 1, stdout: "", stderr: "Error: offline\n" },
    { exitCode: 2, stdout: "", stderr: "Unknown command\n" },
  ];
}

可脚本化输出放 stdout；用法错误与失败信息放 stderr。退出码 0 表示成功，非 0 表示失败类别。本课不调用 process.exit()，避免截断尚未 flush 的输出。

退出码是结果，不是消息

课程约定 0 成功、1 运行失败、2 用法错误；文本仍分别写入正确输出流。

入口职责：读取 argv → parse → execute → 写 stdout/stderr → 设置 process.exitCode。每一步都可以独立测试。

常见误区

  • 把完整 process.argv 交给解析器。Node 与入口路径会被当作命令。
  • parseArgs 后不做语义校验。它不知道 add 需要一个标题。
  • 所有消息都 console.log。脚本无法区分结果与诊断。
  • 在深层函数 process.exit。清理与测试会被突然终止。
  • 返回 string | undefined 表示命令。调用者无法穷尽处理。
  • 为三个命令引入 CLI 框架。Node 标准库已覆盖当前语法。

你要交付什么

type NoteCommand =
  | { readonly kind: "add"; readonly title: string }
  | { readonly kind: "list"; readonly json: boolean }
  | { readonly kind: "help" };

parseNoteCommand(argv: readonly string[]): NoteCommand

运行规则

  • parseArgs 开启 strict 与 allowPositionals，只声明 boolean --json/-j。
  • help 不接受额外参数或 --json。
  • add 必须恰有一个非空标题，且不接受 --json。
  • list 不接受额外位置参数，并保留 json 布尔值。
  • 未知命令与非法组合抛出 Error。

实现限制

使用 node:util.parseArgs；不要读取 process、打印、退出、访问文件、使用 any 或类型断言。Lab 前保留 /** @lab */。

折叠完整答案与逐行解析

import { parseArgs } from "node:util";

export type NoteCommand =
  | { readonly kind: "add"; readonly title: string }
  | { readonly kind: "list"; readonly json: boolean }
  | { readonly kind: "help" };

/** @lab */
export function parseNoteCommand(argv: readonly string[]): NoteCommand {
  const { positionals, values } = parseArgs({
    args: [...argv],
    options: { json: { type: "boolean", short: "j" } },
    allowPositionals: true,
    strict: true,
  });
  const [command, ...rest] = positionals;
  if (command === "list" && rest.length === 0) {
    return { kind: "list", json: values.json ?? false };
  }
  if (command === "add" && rest.length === 1 && rest[0]?.trim() && !values.json) {
    return { kind: "add", title: rest[0] };
  }
  if (command === "help" && rest.length === 0 && !values.json) {
    return { kind: "help" };
  }
  throw new Error("Invalid note command");
}
parseArgs
标准库完成选项词法分析。
解构
把第一个位置参数作为命令，其余作为参数。
分支
每个 kind 同时验证允许的选项和参数数量。
失败
所有无效输入统一拒绝，入口再转换为用法错误。
