持久化先确定路径和编码，再讨论对象

内存对象不会自动成为文件。Node 的 node:fs/promises 负责异步 I/O，node:path 负责平台路径，JSON 负责把可序列化值变成文本；进程当前目录只是路径解析的一个输入。

前置回忆：构建产物与数据文件是两类输出

export function demoTwoOutputs(): string[] {
  return ["dist/cli.js", ".notes/notes.json"];
}

前者由 TypeScript 构建，可从源码重建；后者由应用持久化，包含用户数据。不要用清理构建目录的思路处理数据目录。

详细心智模型：值 → JSON 文本 → 字节 → 文件

1. process.cwd() 是启动位置，不是模块位置

export function demoWorkingDirectory(): boolean {
  return typeof process.cwd() === "string";
}

用户从哪里启动命令，cwd 就可能在哪里。应用若选择 cwd 作为数据根目录，应明确这是产品契约；不要误认为它永远等于源码目录。

2. path.join 使用当前平台分隔符

import path from "node:path";

export function demoJoinedPath() {
  const file = path.join("workspace", ".notes", "notes.json");
  return { file, parent: path.dirname(file) };
}

macOS/Linux 通常得到斜杠，Windows 得到反斜杠。路径值交给 path 模块，URL 与模块说明符则遵循另一套语义。

dirname 找父目录

先得到父目录，再递归创建；不要通过切割字符串猜路径。

3. JSON.stringify 只保存 JSON 数据模型

export function demoJsonBoundary() {
  const note = { id: "n1", title: "Draft", missing: undefined };
  return {
    compact: JSON.stringify(note),
    readable: `${JSON.stringify(note, null, 2)}\n`,
  };
}

输出没有 missing。Date 会变成字符串，Map/Set 不会自动保留语义，循环引用会抛错；因此文件格式必须使用明确的普通对象与数组。

格式化 JSON 便于检查

两个空格和末尾换行让文件适合版本比较与终端查看。

4. Promise I/O 必须按依赖关系 await

export async function demoFileRoundTrip(): Promise<string> {
  const { mkdtemp, readFile, writeFile, rm } = await import("node:fs/promises");
  const { tmpdir } = await import("node:os");
  const directory = await mkdtemp(path.join(tmpdir(), "notes-example-"));
  const file = path.join(directory, "note.txt");
  try {
    await writeFile(file, "Draft", "utf8");
    return await readFile(file, "utf8");
  } finally {
    await rm(directory, { recursive: true, force: true });
  }
}

写入依赖目录存在，读取依赖写入完成，所以顺序 await 是真实因果关系。return await 等待读取结束，再由 finally 清理临时目录，反复点击也不会遗留文件。第 15 课的并发只适合互不依赖的操作。

边界：本课只做直接写入；崩溃时不留下半文件的原子替换将在第 22 课处理。

常见误区

  • 用字符串拼接路径。跨平台分隔符与重复斜杠会出错。
  • 不写 encoding。readFile 默认返回 Buffer。
  • 忘记 await 写入。进程可能在数据落盘前结束。
  • 把 JSON.parse 当成校验。它只保证语法，不能证明字段结构。
  • 直接保存 Map、Error 或 class。JSON 不保留这些运行时语义。
  • 并发写同一文件。writeFile 调用必须由应用串行化。

Lab 18：把 notes 写成明确的 JSON 文件

你要交付什么

type PersistedNote = {
  readonly id: string;
  readonly title: string;
};

persistNotes(
  filePath: string,
  notes: readonly PersistedNote[],
): Promise<void>

运行规则

  • 用 path.dirname(filePath) 得到父目录。
  • 先 mkdir(..., { recursive: true })。
  • 把 notes 复制成普通数组，以两空格格式化并加末尾换行。
  • 用 UTF-8 writeFile，完成后 Promise 才 fulfilled。

实现限制

使用 Node 标准库；不要 catch、同步 I/O、全局 cwd、类型断言或原子临时文件。Lab 前保留 /** @lab */。

三层提示

提示 1 · 父目录

dirname(filePath)。

提示 2 · 稳定文本

await mkdir，再 await writeFile。

怎样生成跨平台文件路径？

折叠完整答案与逐行解析

显示完整答案
import { mkdir, writeFile } from "node:fs/promises";
import path from "node:path";

export type PersistedNote = {
  readonly id: string;
  readonly title: string;
};

/** @lab */
export async function persistNotes(
  filePath: string,
  notes: readonly PersistedNote[],
): Promise<void> {
  await mkdir(path.dirname(filePath), { recursive: true });
  const json = `${JSON.stringify([...notes], null, 2)}\n`;
  await writeFile(filePath, json, "utf8");
}
导入
只用 Promise 文件 API 与平台路径 API。
mkdir
确保嵌套父目录存在。
stringify
复制只读输入，产生可读文本与末尾换行。
writeFile
明确 UTF-8，并把完成状态暴露给调用者。
