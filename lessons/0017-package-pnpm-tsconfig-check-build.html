TOOLCHAIN · PACKAGE CONTRACT · EMIT

检查回答“源码是否合法”，构建回答“运行什么产物”

package.json 描述包与命令入口，pnpm 解析并运行脚本，tsconfig 决定 TypeScript 怎样检查与生成 JavaScript。它们不是三个互相替代的配置文件，而是一条可以逐段验证的执行链。

本课代码文件：创建 src/lesson-17.ts。所有案例保持顶层、命名、零参数导出；带参数的 Lab 前添加 /** @lab */。

详细心智模型：从脚本名追到实际进程

1. package.json 是包边界，也是命令索引

export function demoPackageScripts() {
  const scripts = {
    typecheck: "tsc --noEmit",
    build: "tsc -p tsconfig.build.json",
  };
  return scripts;
}

脚本名是人类稳定入口，值才是被 shell 执行的命令。调用者记住 pnpm typecheck，项目可以在 package.json 中调整实现。

检查不写产物，构建写入 outDir

noEmit 让 TypeScript 只报告类型问题；构建配置关闭 noEmit，并把 JavaScript 写入 outDir。两者共用严格规则，但产物职责不同。

2. packageManager 固定“由谁解释锁文件”

export function demoPackageManagerField(): string {
  const manifest = { packageManager: "pnpm@11.22.0" };
  return manifest.packageManager.split("@")[0] ?? "unknown";
}

它记录包管理器和版本意图；lockfile 固定解析结果。不要混用 npm、pnpm 与 yarn 改写同一个依赖图。

3. include 决定输入，rootDir 决定产物相对结构

export function demoConfigScope(): string {
  const config = {
    include: ["src/**/*.ts"],
    rootDir: "src",
    outDir: "dist",
  };
  return `${config.rootDir} => ${config.outDir}`;
}

rootDir 不会替代 include。它约束需要生成的文件都在根目录下，并保留相对目录结构。

追踪顺序：package script → 本地可执行文件 → tsconfig → include 输入 → 检查诊断或 outDir 产物。

常见误区

  • 把 typecheck 当成 build。noEmit 成功后仍没有可运行文件。
  • 直接调用全局 tsc。项目脚本应使用本地锁定版本。
  • 认为 rootDir 会选择源码。输入集合由 files/include/exclude 决定。
  • 同时维护两套相同配置。构建配置应 extends 基础配置，只覆盖 emit 差异。
  • 忽略失败退出码。脚本链会继续制造误导产物。

Lab 17：从 package scripts 生成构建计划

由你创建或修改：创建 src/lesson-17.ts，保存案例、类型与 Lab。

不要修改：tests/lessons.test.ts 与 scripts/。

你要交付什么

type BuildStepName = "check" | "test" | "build";
type BuildStep = {
  readonly name: BuildStepName;
  readonly command: string;
};

createBuildPlan(
  scripts: Readonly<Record<string, string | undefined>>,
): BuildStep[]

运行规则

  • 固定按 check、test、build 顺序检查。
  • 脚本存在且不是空字符串时加入结果。
  • command 原样保留，不执行、不解析 shell。
  • 不修改输入对象；没有任何脚本时返回空数组。

实现限制

只需一个固定名称数组和循环；不要读取真实 package.json、启动子进程或新增配置抽象。Lab 前保留 /** @lab */。

三层提示

提示 1 · 顺序从哪里来

不要依赖对象键顺序；先定义 ["check", "test", "build"] as const。

提示 2 · 怎样排除空脚本

读取值后检查 command?.trim()，但结果保留原字符串。

提示 3 · 返回什么

命中时 push { name, command }。

折叠完整答案与逐行解析

显示完整答案
export type BuildStepName = "check" | "test" | "build";

export type BuildStep = {
  readonly name: BuildStepName;
  readonly command: string;
};

/** @lab */
export function createBuildPlan(
  scripts: Readonly<Record<string, string | undefined>>,
): BuildStep[] {
  const names = ["check", "test", "build"] as const;
  const plan: BuildStep[] = [];
  for (const name of names) {
    const command = scripts[name];
    if (command?.trim()) plan.push({ name, command });
  }
  return plan;
}
类型
限定允许的步骤名与只读结果字段。
names
显式保存课程要求的执行顺序。
循环
只收集真实、非空的脚本，不替用户猜命令。
返回
结果是计划数据，不产生进程副作用。
