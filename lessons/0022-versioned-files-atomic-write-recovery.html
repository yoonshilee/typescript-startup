VERSIONED FORMAT · TEMP FILE · RENAME · RECOVERY

可靠写入的最低标准：新文件完整后，才替换旧文件

直接 writeFile 目标路径可能在进程中断时留下半截 JSON。版本字段解决“怎样解释数据”，同目录临时文件加 rename 解决“怎样一次切换到新数据”，finally 清理解决“失败后留下什么”。

本课代码文件：创建 src/lesson-22.ts。安全模型实验保持零参数导出；Lab 由课程 HTML 自动识别，无需特殊注释。

任务卡

完成物：实现 writeNotesAtomically(filePath, notes)，写入 { version: 1, notes }，同目录生成唯一临时文件，成功 rename，任何路径都清理临时文件。

  • 用版本号区分文件协议。
  • 区分语法损坏、结构无效与不支持版本。
  • 理解同目录临时文件为何关键。
  • 保证失败不主动删除旧目标文件。

前置回忆：JSON.parse 成功不等于结构可信

export function demoVersionField(): number {
  const file: unknown = JSON.parse('{"version":1,"notes":[]}');
  if (typeof file !== "object" || file === null || !("version" in file)) return 0;
  return file.version === 1 ? 1 : 0;
}

第 21 课的 unknown 校验仍适用于文件读取；version 是选择解析器的协议字段，不是装饰性元数据。

详细心智模型：生成、落盘、切换、清理

1. 版本是格式，不是应用版本

export function demoFileEnvelope() {
  const file = { version: 1, notes: [{ id: "n1", title: "Draft" }] };
  return { file, text: `${JSON.stringify(file, null, 2)}\n` };
}

应用升级不一定改变文件格式；只有持久化协议改变才增加 version。读取器应显式拒绝未知版本或执行已设计迁移。

稳定序列化

明确 envelope、缩进与末尾换行，便于读取、诊断与未来迁移。

2. 损坏分三类

export function demoCorruptionKinds(): string[] {
  return ["invalid JSON", "invalid shape", "unsupported version"];
}

语法错误来自 JSON.parse；结构错误来自运行时校验；版本错误来自协议选择。错误消息可以不同，但都不能悄悄当成空笔记覆盖旧数据。

3. 临时文件必须和目标在同一目录

import path from "node:path";
import { randomUUID } from "node:crypto";

export function demoTempPath(): boolean {
  const target = path.join("data", "notes.json");
  const temporary = path.join(path.dirname(target), `.notes.${randomUUID()}.tmp`);
  return path.dirname(target) === path.dirname(temporary);
}

同目录通常意味着同一文件系统，rename 才能作为一次名字切换。写到系统 tmp 后再跨卷移动可能失败，也失去原子替换保证。

唯一后缀避免并发撞名

每次写入使用独立临时路径；固定 .tmp 文件会让并发调用互相覆盖。

4. rename 之前旧文件保持不变

export function demoAtomicSequence(): string[] {
  return ["write temp", "rename temp to target", "remove leftover temp"];
}

写临时文件失败时，目标未触碰；rename 成功后目标整体变成新内容；finally 对不存在的临时文件使用 force 清理。

5. 危险的直接覆盖不自动运行

function demoDirectOverwrite(): string {
  return "writeFile(target) can truncate before the new payload completes";
}

此函数只说明危险序列，不执行真实覆盖，因此保持非导出，不由运行工具调用。

诚实边界：原子 rename 防止半文件，不等于事务系统；它不解决多进程并发、磁盘硬件保证、备份与跨版本迁移。

常见误区

  • 解析失败就返回空数组。下一次保存会永久覆盖可恢复数据。
  • 临时文件放系统 tmp。跨文件系统 rename 可能失败。
  • 使用固定 .tmp 名。并发写入互相破坏。
  • 先删除目标再 rename。制造没有任何有效文件的窗口。
  • 只在成功时清理。失败会无限堆积临时文件。
  • 声称等同数据库事务。多进程协调和持久化级别尚未解决。

运行规则

  • 递归创建目标父目录。
  • 临时文件位于同一父目录，名称含 randomUUID。
  • 以 flag wx、UTF-8 写入版本 1 envelope、两空格和末尾换行。
  • 写完后 rename 到目标。
  • finally 用 rm(tempPath, { force: true }) 清理。

实现限制

仅用 Node 标准库；不要先删除目标、同步 I/O、catch 后吞错、备份系统或锁。

三层提示

提示 1 · 临时路径

组合 dirname、basename 与 randomUUID，确保同目录。

提示 2 · try 包住什么

writeFile 与 rename 放在 try，rm 放 finally。

import { randomUUID } from "node:crypto";
import { mkdir, rename, rm, writeFile } from "node:fs/promises";
import path from "node:path";

export type VersionedNote = {
  readonly id: string;
  readonly title: string;
};

export async function writeNotesAtomically(
  filePath: string,
  notes: readonly VersionedNote[],
): Promise<void> {
  const directory = path.dirname(filePath);
  await mkdir(directory, { recursive: true });
  const temporaryPath = path.join(
    directory,
    `.${path.basename(filePath)}.${randomUUID()}.tmp`,
  );
  const json = `${JSON.stringify({ version: 1, notes: [...notes] }, null, 2)}\n`;
  try {
    await writeFile(temporaryPath, json, { encoding: "utf8", flag: "wx" });
    await rename(temporaryPath, filePath);
  } finally {
    await rm(temporaryPath, { force: true });
  }
}
目录
目标父目录也是临时文件目录。
唯一名
basename 便于诊断，UUID 避免碰撞。
写入
wx 防止意外覆盖已有临时文件。
切换
只有完整写入后才 rename。
清理
成功与失败都删除可能残留的临时路径。
