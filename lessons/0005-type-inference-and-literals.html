前置回忆：JavaScript 保存值，TypeScript 在运行前检查

前四课已经反复使用 : string、: number 和 : boolean。这些标注不会生成新的 JavaScript 值，也不会在 Node 运行时替你转换输入：

export function demoIncrement(): number {
  function increment(count: number): number {
    return count + 1;
  }

  return increment(2);
}

// increment("3") 写在案例内部时仍会产生类型错误。

运行时只有传入的值、加法与返回结果。类型检查器在运行前证明“这里应该是 number”。本课关注的推断，就是编译器在你没有写全标注时如何得到这些静态事实。

详细心智模型：类型信息从哪里来，为什么会拓宽

1. 推断从已有证据补全类型

变量有初始化值时，TypeScript 通常不需要你重复写同一个事实。函数返回类型也可以从所有 return 表达式得到：

export function inferLocalValues() {
  const title = "Release notes";
  const count = 2;
  const visible = true;

  return `${title}:${count}:${visible}`;
}

编辑器会分别显示 title、count、visible 和函数返回值的类型。Node 运行这段代码时不会保留这些类型；推断只减少重复标注，不改变 JavaScript 行为。

2. 显式标注约束允许赋入的值

参数没有调用前的初始化值，因此公开函数参数通常需要标注。返回类型可以推断，也可以显式写出，用来固定边界并让意外改动尽早报错：

export function demoFormatAttempt(): string {
  function formatAttempt(attempt: number): string {
    const nextAttempt = attempt + 1;
    return `Attempt ${nextAttempt}`;
  }

  return formatAttempt(2);
}

attempt: number 限制调用者，: string 限制实现返回字符串。局部变量 nextAttempt 已经有清楚的数字表达式，重复写 : number 没有增加信息。

3. 字面量类型描述一个精确值

string 表示任意字符串；字面量类型 "active" 只表示这一个字符串值。TypeScript 会根据绑定是否允许重新赋值，选择保留精确值还是拓宽成更通用的类型：

export function compareBindingInference() {
  let changingStatus = "active"; // string
  const fixedStatus = "active";  // "active"

  changingStatus = "archived";
  const annotatedStatus: string = fixedStatus;
  return { fixedStatus, changingStatus, annotatedStatus };
}

let 明确允许以后保存别的字符串，所以推断为 string。const 绑定不能重绑，保留 "active" 这个更精确的类型是安全的。两者最初的运行时值完全相同。

显式宽类型会丢失精度

fixedStatus 是精确字面量 "active"，而显式标注把 annotatedStatus 固定为更宽的 string。标注不是天然“更严格”；写得过宽反而会丢失编译器本来能保留的信息。

4. const 对象的属性仍然可变，所以属性会拓宽

const 固定的是变量 options 与对象之间的引用，不会固定对象属性。为了允许下一行合法赋值，status 通常会从 "active" 拓宽为 string：

export function demoPropertyWidening(): string {
  const options = { status: "active", limit: 20 };

  options.status = "archived";
  options.limit = 50;
  return `${options.status}:${options.limit}`;
}

执行顺序是：创建对象，保存初始属性，再修改两个属性，最后返回 "archived:50"。如果属性类型仍是精确的 "active" 与 20，这些正常修改就会被错误拒绝，因此编译器主动拓宽。

5. as const 明确要求保留字面量

当数据表达固定协议、默认配置或命令常量时，可以在字面量表达式后写 as const：

export function preserveDefaultOptions() {
  const options = {
    status: "active",
    limit: 20,
  } as const;

  return options;
}

现在编译器把属性看成只读的精确值：status 是 "active"，limit 是 20。因此 options.status = "archived" 会在类型检查时报错。这里没有要求你手写对象类型；第 06 课才系统讲 type、interface、可选属性和 readonly。

6. as const 不是运行时冻结

as const 是 const assertion，只影响类型检查，不会调用 Object.freeze()，也不会递归复制已经存在的引用。下面的数组先单独创建，再放进对象；它仍然是可修改的同一个数组：

export function demoConstBoundary(): string[] {
  const tags = ["typescript"];
  const options = { tags } as const;

  options.tags.push("node");
  return tags; // ["typescript", "node"]
}

options.tags 这个属性不能被重新指向另一个数组，但现有数组仍可通过 push 修改。这与第 04 课的浅复制边界一致：静态只读属性、运行时冻结和深度不可变是三件不同的事。

7. 上下文也能提供推断证据

推断不只看右侧初始化值。数组已经是 string[] 时，map 的回调参数会从调用位置得到 string，函数返回值则从 map 的结果得到 string[]：

export function demoTagNormalization() {
  function normalizeTags(tags: string[]) {
    return tags.map((tag) => tag.trim().toLowerCase());
  }

  return normalizeTags([" TypeScript ", " Node "]);
}

这里无需给 tag 和函数返回值再次标注。若把回调独立放到没有上下文的位置，参数就需要自己的标注。后面的函数类型课程会系统解释这种“从使用位置反推”的上下文类型。

默认策略：参数和需要稳定承诺的公开边界写标注；有明确初始化值的局部变量优先让编译器推断；只有确实要保留精确字面量时才使用 as const。

Java 的 var 与 TypeScript 推断最接近：都是编译期确定静态类型，不等于 Python 名称可以在运行时绑定不同类型。TypeScript 特有的关键点是，它会根据未来可能的赋值把精确字面量拓宽。

补充观察与运行

示例 A：局部计算不需要重复标注

export function demoRemaining(): number {
  function calculateRemaining(total: number, completed: number): number {
    const remaining = total - completed;
    return Math.max(remaining, 0);
  }

  return calculateRemaining(5, 2);
}

参数与公开返回承诺有标注；remaining 的类型从减法表达式得到。写成 const remaining: number 只是重复编译器已经知道的事实。

示例 B：数组字面量默认允许后续追加

export function buildMutableTags(): string[] {
  const tags = ["typescript", "node"];
  tags.push("cli");
  return tags;
}

变量本身是 const，数组内容仍可修改，因此元素会推断为通用的 string。对数组字面量使用 as const 会保留顺序、长度与每个精确元素，并拒绝 push；本课 Lab 先用更简单的对象属性观察同一规则。

示例 C：as const 适合固定协议值

export function createFixedCommand() {
  return {
    command: "list",
    format: "json",
  } as const;
}

两个属性都是协议中的固定值，而不是随后要编辑的表单状态。这里保留字面量有明确目的；若对象确实要变化，就不应为了“类型更窄”强行添加 as const。

常见误区

  1. 给每个局部变量都写类型。 重复标注增加修改成本，也可能把本来精确的推断写宽。
  2. 认为类型标注会转换值。 count: number 不会把字符串 "3" 变成数字。
  3. 把 const 当成对象不可变。 它只阻止变量重新绑定；对象属性和数组内容默认仍可变。
  4. 把 as const 当成 Object.freeze()。 const assertion 不生成运行时代码，也不验证外部数据。
  5. 为了更窄的类型到处使用 as const。 真正需要修改的数据不该伪装成固定协议值。
  6. 用 assertion 掩盖不确定输入。 外部 JSON 与用户输入需要运行时校验；as const 不能证明它们可信。
