前置回忆：rootDir 保留相对目录结构

export function demoEmitMapping(): string {
  return "src/cli.ts -> dist/cli.js";
}

第 17 课的 build 配置把 src 作为 rootDir、dist 作为 outDir。bin 必须指向构建后实际存在的路径。

详细心智模型：命令名 → 链接 → bin 目标 → Node

1. bin 映射公开命令名

export function demoBinManifest(): object {
  return { bin: { notes: "./dist/cli.js" } };
}

安装包时，包管理器为 notes 创建可执行链接或 Windows shim。目标是包内相对路径，不是开发机绝对路径。

2. shebang 必须位于产物第一行

export function demoShebang(): string {
  return "#!/usr/bin/env node";
}

类 Unix 直接执行文件时由内核读取这一行；Windows 通常由包管理器生成的 shim 启动 Node。TypeScript 会把 shebang 保留到 JavaScript 产物。

3. 文件系统路径交给 node:path

import path from "node:path";
import { fileURLToPath, pathToFileURL } from "node:url";

export function demoPaths() {
  const filePath = path.resolve("dist", "cli.js");
  const fileUrl = pathToFileURL(filePath);
  return {
    absolute: filePath,
    bin: "./dist/cli.js",
    name: path.basename(filePath),
    url: fileUrl.href,
    roundTrip: fileURLToPath(fileUrl) === filePath,
  };
}

path.resolve 使用当前平台规则并产生绝对路径。不要在领域逻辑中假定 / 或盘符。

围绕同一个入口依次看 absolute、bin、name、url 与 roundTrip；不必为每种路径表示重新声明一套文件名。

import.meta.url 是 URL，不是普通路径

模块位置从 import.meta.url 开始时先用 fileURLToPath；需要动态 import 路径时反向用 pathToFileURL。不要手工移除 file://。

绝对入口与包内目标不同

前者用于当前机器文件操作；后者存入可搬移的 package.json。

basename 可验证产物名

name 是 cli.js，roundTrip 是 true；测试不应硬编码整个机器绝对路径。

4. ESM 相对导入写运行时扩展名

export function demoRuntimeSpecifier(): string {
  return "import { main } from './main.js'";
}

Node 最终解析 JavaScript 文件。当前 TypeScript 配置允许源码使用可重写扩展名，但构建产物必须形成 Node 可解析的说明符。

验收链：pnpm build → dist/cli.js 存在且首行 shebang → package bin 指向该文件 → 临时安装后运行 notes --help。

常见误区

  • bin 指向 src/cli.ts。消费者不应依赖 TypeScript 运行支持。
  • shebang 前有空行。Unix 内核不会把它识别为解释器声明。
  • 手工拼接绝对路径。Windows 盘符与分隔符会出错。
  • 把 file URL 当路径。百分号编码与平台格式会被破坏。
  • 只验证 node dist/cli.js。还要验证包管理器创建的命令入口。
  • 提交所有构建产物。课程仓库只需可重建并在验收时生成。

你要交付什么

type CliPaths = {
  readonly source: string;
  readonly output: string;
  readonly binTarget: "./dist/cli.js";
};

resolveCliPaths(projectRoot: string): CliPaths

运行规则

  • 先用 path.resolve(projectRoot) 规范化根目录。
  • source 用 path.join 指向 src/cli.ts。
  • output 用 path.join 指向 dist/cli.js。
  • binTarget 保持包内 POSIX 风格字面量 ./dist/cli.js。
  • 不访问文件系统。

实现限制

只使用 node:path；不要检查文件存在、改 cwd、读取 package.json 或按平台分支。

保存 src/lesson-23.ts 后，点击下方“校验练习”查看通过或失败结果；这与 pnpm lesson 23 使用同一套运行时与类型契约测试，不会执行折叠答案。

折叠完整答案与逐行解析

显示完整答案
import path from "node:path";

export type CliPaths = {
  readonly source: string;
  readonly output: string;
  readonly binTarget: "./dist/cli.js";
};

export function resolveCliPaths(projectRoot: string): CliPaths {
  const root = path.resolve(projectRoot);
  return {
    source: path.join(root, "src", "cli.ts"),
    output: path.join(root, "dist", "cli.js"),
    binTarget: "./dist/cli.js",
  };
}
root
一次规范化，避免每个字段重复解析。
source/output
文件系统路径由平台 API 组合。
binTarget
包内相对目标是稳定发布契约。
纯函数
这里只描述路径，不承担文件存在性检查。
