详细心智模型：可观察输入、行为与输出

1. assert 抛出才会让测试失败

import assert from "node:assert/strict";

export function demoStrictAssertion(): string {
  assert.equal(1 + 1, 2);
  const first = { id: "n1" };
  const second = { id: "n1" };
  assert.notEqual(first, second);
  assert.deepEqual(first, second);
  return "passed";
}

equal 适合原始值或对象身份，deepEqual 比较结构。打印 actual 与 expected 但不 assert，测试仍会错误地通过。

对象身份不等于结构相等

notEqual 验证 first 与 second 不是同一对象，deepEqual 验证它们的数据结构相等。两条断言同时通过才返回 passed；选择 assertion 前先明确比较的是身份还是数据。

2. async 测试返回 Promise

export async function demoRejectedPromise(): Promise<string> {
  await assert.rejects(
    Promise.reject(new Error("offline")),
    /offline/,
  );
  return "rejection observed";
}

test callback 返回的 Promise 若拒绝，runner 自动失败。必须 await assert.rejects，否则测试可能在断言完成前结束。

3. 文件测试使用唯一目录

import { mkdtemp, rm } from "node:fs/promises";
import { tmpdir } from "node:os";
import path from "node:path";

export async function demoTemporaryDirectory(): Promise<boolean> {
  const directory = await mkdtemp(path.join(tmpdir(), "notes-test-"));
  try {
    return path.isAbsolute(directory);
  } finally {
    await rm(directory, { recursive: true, force: true });
  }
}

唯一目录避免并行测试互相覆盖；finally 保证成功与失败都清理。不要把测试数据写进仓库或用户真实目录。

4. 测试名描述行为，不复述函数名

export function demoBehaviorName(): string {
  return "reports each duplicate id once in encounter order";
}

失败报告应直接说明哪个契约破坏。一个测试可覆盖一个紧密行为，边界案例则用独立输入表达。

调试循环：先得到稳定红灯 → 缩小输入 → 检查真实值 → 修根因 → 保留最小回归测试。

常见误区

  • 只看“没有抛错”。没有断言的测试证明不了结果。
  • 忘记 await rejects。异步断言可能逃出测试生命周期。
  • 复用固定临时路径。并发或上次残留会污染结果。
  • 测试私有实现步骤。重构会造成无意义破坏。
  • 一次塞入十个行为。失败时无法定位哪条契约断裂。
  • 先改代码再找复现。无法确认测试真的捕获原问题。

Lab 20：找出重复 note id

由你创建或修改：创建 src/lesson-20.ts，保存案例、DuplicateNote 与 Lab。

你要交付什么

type DuplicateNote = { readonly id: string };

findDuplicateNoteIds(
  notes: readonly DuplicateNote[],
): string[]

运行规则

  • 第一次出现只记录 seen。
  • 第二次出现把 id 加入结果。
  • 第三次及以后不重复报告同一 id。
  • 结果按各 id 第二次出现的顺序排列。
  • 不修改输入。

实现限制

使用两个 Set 与一次循环；不要排序、嵌套扫描、Map 计数或类型断言。Lab 前保留 /** @lab */。

三层提示

提示 1 · 两种状态

一个 Set 表示见过，另一个表示已经报告。

提示 2 · 何时 push

seen 有 id 且 duplicates 没有时。

提示 3 · 一次循环

每次处理后确保 seen 包含当前 id。

折叠完整答案与逐行解析

显示完整答案
export type DuplicateNote = { readonly id: string };

/** @lab */
export function findDuplicateNoteIds(
  notes: readonly DuplicateNote[],
): string[] {
  const seen = new Set<string>();
  const reported = new Set<string>();
  const duplicates: string[] = [];
  for (const { id } of notes) {
    if (seen.has(id) && !reported.has(id)) {
      duplicates.push(id);
      reported.add(id);
    }
    seen.add(id);
  }
  return duplicates;
}
集合
seen 与 reported 分别表达两个可测试状态。
条件
只在第二次首次发现重复时记录。
顺序
push 自然保留第二次出现顺序，无需排序。
复杂度
单次遍历，输入保持只读。
