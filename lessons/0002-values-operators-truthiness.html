详细心智模型：值、绑定、操作与布尔上下文

1. const 与 let 约束的是绑定

变量名把当前作用域中的一个名字绑定到值。const 表示这个名字不能重新绑定；它不承诺对象内部不可变。let 允许重新绑定。现代 TypeScript 默认先用 const，只有确实需要给同一名字赋新值时再用 let；本课程不使用函数作用域且易产生提升困惑的 var。

export function demoBindingMutation(): string {
  const tags = ["typescript"];
  tags.push("node");       // Allowed: the array object changed.

  let status = "draft";
  status = "published";   // Allowed: the binding changed.

  return `${status}: ${tags.join(", ")}`;
}

第一段没有重新给 tags 赋值；数组本身被修改。第 04 课会系统处理可变与不可变更新。

2. JavaScript 的原始值集合

常见原始值是 string、number、boolean、undefined、null、bigint 和 symbol。除它们之外，数组、函数、日期和正则表达式都属于对象。原始值本身不可变：字符串方法会返回新字符串，不会在原位置改写字符。

3. number 同时承担整数与小数

JavaScript 没有日常使用中的 int、long、float、double 分家。42 与 3.14 都是 number。这让 API 简洁，也意味着你必须知道浮点误差、安全整数范围和特殊数值。

export function inspectNumberValues() {
  const parsed = Number("not-a-number");

  return {
    nan: Number.isNaN(parsed),
    type: typeof parsed,
    // @ts-expect-error — NaN never equals itself.
    equalsItself: parsed === NaN,
    finite: Number.isFinite(Infinity),
    safeInteger: Number.isSafeInteger(9_007_199_254_740_991),
    exactDecimal: 0.1 + 0.2 === 0.3,
  };
}

涉及货币时，不能天真地把小数金额连续相加。常见做法是用最小货币单位的安全整数，或选择经过验证的十进制方案；本课程的 Notes CLI 不处理货币，因此不引入额外库。

NaN 是 number，但不等于自己

NaN 表示某次数值运算没有产生有效数字。检测它应使用 Number.isNaN，而不是与 NaN 比较。

4. 运算符可能转换值，严格相等尽量拒绝猜测

+ 同时支持数值加法和字符串拼接。当任一操作数触发字符串转换时，结果可能不是你想的算术。== 会执行复杂的隐式转换；=== 不做这类类型转换，因此是课程默认。

export function compareOperators() {
  const addition = 1 + 2;          // 3
  const concatenation = "1" + 2;  // "12"
  // @ts-expect-error — JavaScript coerces this string at runtime.
  const subtraction = "5" - 2;    // 3
  // @ts-expect-error — TypeScript warns about comparing unrelated types.
  const looseEquality = 0 == false;  // true
  // @ts-expect-error — TypeScript warns about comparing unrelated types.
  const strictEquality = 0 === false; // false

  return { addition, concatenation, subtraction, looseEquality, strictEquality };
}

Object.is 与 === 基本相似，但特殊处理 NaN 与正负零：Object.is(NaN, NaN) 为 true，Object.is(0, -0) 为 false。日常业务比较优先 ===；只有特殊数值语义需要时再用 Object.is。

5. truthiness 是转成布尔值的规则，不是“非空集合”规则

条件语句会把表达式转换成布尔值。假值只有有限集合：false、0、-0、0n、""、null、undefined 和 NaN。其余值都是真值，包括字符串 "false"、空数组 [] 和空对象 {}。

export function inspectTruthiness() {
  const rawTitle = "   ";

  return {
    whitespace: Boolean(rawTitle),
    meaningful: rawTitle.trim().length > 0,
    emptyString: Boolean(""),
    falseText: Boolean("false"),
    emptyArray: Boolean([]),
    emptyObject: Boolean({}),
    notANumber: Boolean(NaN),
  };
}

字符串清理必须显式

原字符串包含空格，所以是真值；业务上却没有可见标题。把业务谓词完整写出来，代码才说明真实意图。

实践规则：如果业务条件是“字符串去掉空白后有内容”，就直接写这个条件；不要把笼统的 truthiness 当成精确业务规则。

补充观察与运行

示例 A：默认值运算符的语义不同

export function compareDefaultOperators() {
  const requestedLimit = 0;

  const looseDefault = requestedLimit || 20;   // 20
  const nullishDefault = requestedLimit ?? 20; // 0

  return { looseDefault, nullishDefault };
}

|| 在左侧为任何假值时选择右侧；?? 只在左侧为 null 或 undefined 时选择右侧。如果 0 是合法值，?? 更符合“缺失才使用默认值”的业务含义。

示例 B：对象相等比较的是身份

export function compareObjectIdentity() {
  const first = { id: "note-1" };
  const second = { id: "note-1" };
  const alias = first;

  return {
    sameContent: first === second,
    sameReference: first === alias,
  };
}

两个对象内容相同也不是同一个对象。后续测试不能用 === 判断深层结构相等，而要使用专门的深度断言。

常见误区

  1. 用 let 表示对象会变化。 只有变量需要重新绑定时才需要 let；对象内部变化与绑定变化是两件事。
  2. 相信 == 会“方便地帮忙”。 隐式转换规则复杂且输入边界难以推断；默认使用 ===。
  3. 用 value || fallback 处理所有默认值。 合法的 0、空字符串或 false 会被覆盖；缺失语义通常用 ??。
  4. 把 NaN 当成非 number。 typeof NaN 是 "number"，必须用专门谓词检查。
  5. 沿用 Python 空集合为假的直觉。 JavaScript 中任何数组和普通对象都是真值。
  6. 用浮点数直接表示需要精确十进制的业务。 先明确精度模型，再选择表示方法。

三层提示

提示 1 · 分成两个概念步骤

先得到去掉首尾空白的新字符串，再判断这个新字符串是否还有字符。

提示 2 · 找到两个成员

字符串的 trim() 返回清理后的新字符串；字符串的 length 是字符单元数量。

提示 3 · 写出布尔表达式

比较 title.trim().length 是否大于零，比较表达式本身已经产生 boolean，不需要额外三元表达式。

折叠完整答案与逐行解析

显示完整答案 
export function isMeaningfulTitle(title: string): boolean {
  return title.trim().length > 0;
}
第 1 行
静态契约要求输入是 string，结果一定是 boolean；函数导出供黑盒测试调用。
第 2 行
trim() 创建去除两端空白的新字符串；length > 0 直接生成精确布尔值。
第 3 行
没有修改传入字符串，也没有可观察副作用。
