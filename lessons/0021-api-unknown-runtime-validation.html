UNKNOWN · JSON · STRUCTURAL VALIDATION

外部数据先是 unknown，通过证据后才是领域对象

HTTP 响应、JSON 文件、环境变量和用户输入不会因为写了 TypeScript 类型就改变。类型断言只改变编译器判断；运行时校验必须逐层证明容器、字段与元素满足契约。

本课代码文件：创建 src/lesson-21.ts。安全实验是顶层零参数导出函数；Lab 由课程 HTML 自动识别，无需特殊注释。危险案例保持非导出。

任务卡

完成物：实现 parseApiNote(value)，验证非空对象、id、title 与字符串 tags，并返回拥有独立 tags 数组的 ApiNote。

  • 理解 JSON.parse 与 response.json 的结果应视作 unknown。
  • 按容器 → 属性 → 元素顺序收窄。
  • 区分检查事实与类型断言。
  • 在信任边界拒绝损坏数据，不让错误扩散进领域层。

前置回忆：catch 从 unknown 开始

export function demoUnknownValue(): string {
  const value: unknown = JSON.parse("42");
  return typeof value;
}

第 16 课对错误值先收窄；外部数据同理。JSON 语法正确只说明能产生 JavaScript 值，不说明它是 Note。

详细心智模型：每次访问都要有前置证据

1. typeof null 也是 object

export function demoObjectCheck(): boolean[] {
  const values: unknown[] = [null, [], {}];
  return values.map((value) =>
    typeof value === "object" && value !== null && !Array.isArray(value)
  );
}

结果是 [false, false, true]。对象检查必须排除 null 与数组，之后才能把它当作键值容器继续检查。

2. 属性存在不代表类型正确

export function demoPropertyEvidence(): boolean {
  const value: Record<string, unknown> = { title: 42 };
  return typeof value.title === "string";
}

结果 false。结构化类型在编译期工作，运行时需要逐字段 typeof、Array.isArray 或更具体谓词。

3. 数组还要检查每个元素

export function demoArrayElements(): boolean {
  const tags: unknown = ["ts", 24];
  return Array.isArray(tags) &&
    tags.every((tag) => typeof tag === "string");
}

Array.isArray 只证明容器；every 才证明元素。空数组会通过 every，正符合“所有元素都是字符串”。

4. 断言不会产生运行时保护

function demoUnsafeAssertion(): string {
  const value: unknown = { title: 42 };
  return (value as { title: string }).title.toUpperCase();
}

这会在运行时抛错，因此故意不导出，不由运行工具调用。as 没检查 42，也没转换它；它只是要求编译器相信作者。

5. 校验后复制边界集合

export function demoBoundaryCopy() {
  const source = { id: "n1", title: "Draft", tags: ["ts"], debug: true };
  // Assume these fields have passed the checks above.
  const { id, title, tags } = source;
  const accepted = { id, title, tags: [...tags] };
  source.tags.push("node");
  return { accepted, isolated: accepted.tags.length === 1 };
}

复制 tags 防止外部对象在解析后继续改变领域值。冻结整个对象不是本课要求，只需不共享可变数组引用。

accepted 只含 id、title、tags；debug 未被带入，原数组追加 node 后 accepted.tags 仍只有 ts。

解析结果重新构造

只把已验证字段带入领域对象，额外外部字段不会悄悄扩散。

证明链：unknown → 非空普通对象 → 字段存在且类型正确 → 数组元素正确 → 新领域对象。

常见误区

  • 给 response.json 标注 ApiNote。标注不能改变服务器响应。
  • 只检查 typeof object。null 与数组也会混入。
  • 只检查 tags 是数组。元素仍可能是数字或对象。
  • 用 as 跳过检查。错误只会推迟到更远处爆炸。
  • 返回原始外部对象。额外字段与共享引用继续越过边界。
  • 错误消息依赖完整 JSON。可能泄露大体积或敏感数据。

你要交付什么

type ApiNote = {
  readonly id: string;
  readonly title: string;
  readonly tags: readonly string[];
};

parseApiNote(value: unknown): ApiNote

运行规则

  • value 必须是非 null、非数组对象。
  • id 与 title 必须是非空白字符串。
  • tags 必须是数组，且每项都是字符串。
  • 成功保留原 id/title 文本，复制 tags 后返回新对象。
  • 任一检查失败抛出 Error("Invalid API note")。

实现限制

从 unknown 逐层收窄；不要使用 any、as、非空断言、JSON stringify 比较或外部校验库。

保存 src/lesson-21.ts 后，点击下方“校验练习”查看通过或失败结果；这与 pnpm lesson 21 使用同一套运行时与类型契约测试，不会执行折叠答案。

折叠完整答案与逐行解析

显示完整答案
export type ApiNote = {
  readonly id: string;
  readonly title: string;
  readonly tags: readonly string[];
};

export function parseApiNote(value: unknown): ApiNote {
  function isRecord(input: unknown): input is Record<string, unknown> {
    return typeof input === "object" && input !== null && !Array.isArray(input);
  }

  if (!isRecord(value)) throw new Error("Invalid API note");
  const { id, title, tags } = value;
  if (
    typeof id !== "string" || !id.trim() ||
    typeof title !== "string" || !title.trim() ||
    !Array.isArray(tags) ||
    !tags.every((tag) => typeof tag === "string")
  ) {
    throw new Error("Invalid API note");
  }
  return { id, title, tags: [...tags] };
}
局部 isRecord
只服务 Lab，在函数内部建立可读取字符串键的证据。
字段检查
分别证明文本、非空约束、数组与元素。
失败
边界立即拒绝，不返回部分对象。
成功
只返回领域字段并复制集合。
