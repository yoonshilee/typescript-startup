联合列出所有可能，控制流逐步排除不可能

联合类型不是“放弃确定性”，而是把有限可能写进契约。你将用真实 JavaScript 检查缩小候选集合，用共同字面量字段建立判别联合，并让 never 在新增分支未处理时触发编译错误。

前置回忆：字面量可以成为类型，对象契约可以共享字段

第 05 课看到 "active" 这样的精确字面量类型，第 06 课用对象类型描述成员。把两者组合，就能让一个共同字段精确指出当前对象是哪种变体：

type DraftState = {
  kind: "draft";
  title: string;
};

type PublishedState = {
  kind: "published";
  url: string;
};

这里还没有联合；只是两个独立对象类型。下一步用竖线把它们组成“草稿或已发布”的有限集合。

详细心智模型：候选集合如何随控制流变化

1. 联合类型表示候选之一，不是同时拥有两边

export function demoIdentifier(): string {
  function formatIdentifier(id: string | number): string {
    if (typeof id === "string") {
      return id.toUpperCase();
    }

    return id.toFixed(0);
  }

  return formatIdentifier("n1");
}

string | number 表示一次调用中的值要么是字符串，要么是数字。进入函数时还不知道是哪一个，所以不能直接调用只属于字符串的 toUpperCase()。联合不是交叉：它不会让一个值同时拥有两种类型的全部成员。

2. 收窄依赖真实运行时检查

typeof id === "string" 会在运行时产生布尔值；TypeScript 同时把真分支中的候选从 string | number 缩小为 string。真分支已经 return 后，后续路径只剩 number：

  1. 函数入口：id 可能是 string 或 number。
  2. 真分支：检查证明它是 string，可以调用字符串方法。
  3. 真分支返回：该路径结束。
  4. 剩余路径：string 已排除，只能是 number。

这叫控制流分析。标注没有改变；编译器根据已经发生的检查、返回与赋值，在不同代码位置维护更精确的当前类型。

3. 数组用 Array.isArray 收窄

export function demoTermCount(): number {
  function countSearchTerms(value: string | string[]): number {
    if (Array.isArray(value)) {
      return value.length;
    }

    return value.trim().length > 0 ? 1 : 0;
  }

  return countSearchTerms(["typescript", "node"]);
}

typeof [] 在 JavaScript 中是 "object"，不能区分普通对象与数组。Array.isArray(value) 才是平台提供的数组检查，TypeScript 能把真分支收窄为 string[]。

4. 对象变体可以用 in 检查成员

type NotePointer =
  | { id: string }
  | { index: number };

export function demoPointer(): string {
  function formatPointer(pointer: NotePointer): string {
    if ("id" in pointer) {
      return `id:${pointer.id}`;
    }

    return `index:${pointer.index}`;
  }

  return formatPointer({ id: "n1" });
}

"id" in pointer 是真实 JavaScript 属性检查。真分支保留包含 id 的成员，假分支只剩包含 index 的成员。若属性在某个成员中是可选的，它可能同时出现在真假两侧，所以不要把可选属性当作最稳定的判别字段。

5. 判别联合给每个成员相同的字面量字段

type NoteLookup =
  | { found: true; title: string }
  | { found: false };

export function demoLookup(): string {
  function describeLookup(result: NoteLookup): string {
    if (result.found) {
      return `Found:${result.title}`;
    }

    return "Not found";
  }

  return describeLookup({ found: true, title: "TypeScript" });
}

两个成员都有 found，但值分别固定为 true 和 false。检查该字段后，TypeScript 知道真分支一定有 title。这种共同的字面量字段叫 discriminant；整个联合叫 discriminated union。

6. 判别字段把每个 payload 与自己的命令绑定

命令成员判别字段该成员独有数据
addkind: "add"title: string
listkind: "list"无
showkind: "show"id: string
searchkind: "search"query: string
archivekind: "archive"id: string
importkind: "import"path: string
exportkind: "export"path: string

这里的 payload 不是名为 payload 的属性，而是“执行该命令所需数据”的统称：add 需要 title，show 需要 id，search 需要 query，list 则不需要额外数据。“绑定”表示把 kind 与这些必需字段之间的关系写进类型。

一个全是可选字段的对象没有建立关系

type LooseCommand = {
  kind: "add" | "list" | "show";
  title?: string;
  id?: string;
};

export function demoLooseCommandProblem(): string {
  const invalid: LooseCommand = {
    kind: "show",
  };

  return invalid.kind;
}

这个对象能通过类型检查，因为 id? 允许 id 缺少。kind 的值虽然是 show，却没有任何规则要求 show 必须同时拥有 id；同样也能写出带 id、却缺少 title 的 add 命令。

联合的每一行都是一个不可拆散的完整候选

type BoundCommand =
  | { kind: "add"; title: string }
  | { kind: "list" }
  | { kind: "show"; id: string };

export function demoBoundCommand(): string {
  function describeBoundCommand(command: BoundCommand): string {
    switch (command.kind) {
      case "add":
        return `add:${command.title}`;
      case "list":
        return "list";
      case "show":
        return `show:${command.id}`;
    }
  }

  return describeBoundCommand({ kind: "show", id: "n1" });
}

// const invalid: BoundCommand = { kind: "show" };
// 类型错误：show 成员必须同时提供 id。
  1. 创建对象时，kind: "show" 只能匹配联合中的 show 成员。
  2. show 成员同时要求 id: string，所以缺少 id 的对象无法完成赋值。
  3. 函数入口仍有三个候选，只能安全读取它们共同拥有的 kind。
  4. 进入 case "show" 后，add 与 list 被排除，只剩带 id 的 show 成员，因此可以直接读取 command.id。

运行时仍然只是普通对象、字符串比较和属性读取；类型不会创建隐藏连接，也不会验证 JSON 等外部输入。对于直接书写的对象字面量，编译器还会报告与当前成员无关的多余 payload；真正的运行时边界会在第 08 课处理。

7. switch 会按判别字段逐分支收窄

type SaveState =
  | { kind: "idle" }
  | { kind: "saved"; path: string }
  | { kind: "failed"; message: string };

export function demoSaveState(): string[] {
  function describeSaveState(state: SaveState): string {
    switch (state.kind) {
      case "idle":
        return "Idle";
      case "saved":
        return `Saved:${state.path}`;
      case "failed":
        return `Failed:${state.message}`;
      default:
        return assertNever(state);
    }
  }

  return [
    describeSaveState({ kind: "saved", path: "notes.json" }),
    describeSaveState({ kind: "idle" }),
    describeSaveState({ kind: "failed", message: "offline" }),
  ];
}

每个 case 都排除其他字面量成员，所以可以安全读取该成员独有的字段。分支直接返回后不会发生 fall-through；本项目同时启用了 noFallthroughCasesInSwitch。

一次运行依次观察 saved、idle、failed。尝试在 SaveState 中增加 saving 成员，并检查下方 assertNever(state) 的诊断。

8. never 表示已经没有可能值

function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${JSON.stringify(value)}`);
}

在全部 case 都处理完后，state 的所有联合成员已被排除，因此默认分支中的类型是 never。assertNever 只接受 never，也永远不会正常返回。

收窄由 switch 的控制流分析完成；never 是检查遗漏的报警器，不是负责收窄的东西。下面的编译错误是在保留 assertNever(state) 及其 never 参数约束时发生的。

以后若给 SaveState 新增 { kind: "saving" } 却忘记更新 switch，默认分支中的 state 就会是新成员而不是 never，于是调用 assertNever(state) 在编译时失败。这把“记得更新每个分支”变成可验证契约。

设计顺序：先列出真实互斥状态，为每个成员选择稳定的共同字面量字段，再在控制流中检查该字段。不要先写大量 as 断言；如果每个分支都需要断言，通常是联合形状缺少可靠判别。

Java 开发者可以把判别联合理解为无需类层次的 sealed variants；Python 开发者可以把它理解为由 Literal 字段标记的 Union。不同点仍是：TypeScript 类型会擦除，运行时真正发生的是普通属性读取和条件分支。

补充观察与运行

示例 A：共同操作不一定需要分支

export function demoKeyString(): string {
  function stringifyKey(key: string | number): string {
    return String(key);
  }

  return stringifyKey(7);
}

String(value) 接受两种候选，因此不必为了使用联合而强行分支。只有操作依赖某个成员独有能力时才收窄。

示例 B：提前返回让剩余路径更精确

export function demoQuery(): string[] {
  function normalizeQuery(query: string | string[]): string[] {
    if (Array.isArray(query)) {
      return query.map((item) => item.trim());
    }

    return [query.trim()];
  }

  return normalizeQuery(" typescript ");
}

真分支直接返回数组转换结果；剩余路径自动排除数组，只处理一个字符串。无需额外 else 或类型断言。

示例 C：布尔判别字段绑定成功数据

type ParseCountResult =
  | { ok: true; value: number }
  | { ok: false; message: string };

export function demoParseCount(): string {
  function formatParseCount(result: ParseCountResult): string {
    if (result.ok) {
      return `Count:${result.value}`;
    }

    return `Error:${result.message}`;
  }

  return formatParseCount({ ok: true, value: 2 });
}

成功成员一定有 value，失败成员一定有 message，不会出现 ok: true 却缺少结果的对象。完整的 Result 错误传播会在第 16 课建立。

常见误区

  1. 未收窄就访问成员独有属性。 联合位置只保证所有候选都拥有的能力。
  2. 把 | 当成同时满足两边。 联合表示候选之一；同时满足属于后续的交叉类型。
  3. 用可选字段拼出互斥状态。 它会允许缺 payload 或多个 payload 同时存在。
  4. 用 as 告诉编译器当前成员。 优先用真实运行时检查，让控制流提供证据。
  5. 写了 switch 却没有穷尽检查。 新增联合成员时旧代码可能静默漏分支。
  6. 把 never 理解成 undefined。 never 表示根本没有可出现的值，不是某个空值。

Learning Contract

进入空值与未知边界前，你应当能够：

  • 读写基础联合与多行对象联合，并说明每个成员的合法值。
  • 在未收窄位置识别所有成员共同支持的操作。
  • 选择 typeof、Array.isArray、in 或判别字段提供真实运行时证据。
  • 根据分支、提前返回和 switch 预测当前变量的收窄结果。
  • 设计不允许无效状态的判别联合，并用 never 锁定穷尽处理。

你要交付什么

导出 NoteCommand 类型和 describeCommand(command: NoteCommand): string。另写一个不导出的 assertNever(value: never): never，在 switch 默认分支中调用。

NoteCommand 的七个精确成员

kind完整成员返回字符串
add{ kind: "add"; title: string }add:${title}
list{ kind: "list" }list
show{ kind: "show"; id: string }show:${id}
search{ kind: "search"; query: string }search:${query}
archive{ kind: "archive"; id: string }archive:${id}
import{ kind: "import"; path: string }import:${path}

describeCommand 必须按什么规则工作

  1. 使用 switch (command.kind)，为七个字面量分别写 case。
  2. 每个 case 只读取当前成员拥有的 payload，并立即返回表格中的精确字符串。
  3. 不要清理、改写或验证 payload；本课只训练类型分支。
  4. default 调用 assertNever(command)，让新增成员未处理时无法通过类型检查。

完成条件

  • 七种合法命令都有精确运行结果。
  • 无效 kind、缺少必需 payload、错误 payload 类型和多余 payload 都被拒绝。
  • 每个 case 内无需类型断言即可读取独有字段。
  • 完整答案加入第八个成员但不加 case 时，assertNever(command) 必须产生编译错误。

本课只把命令建模并输出可观察描述，不解析终端参数、不执行命令、不读写文件。真正 CLI 协议在第 19 课实现。

三层提示

提示 1 · 先写完整联合

每行以竖线开头写一个对象成员，所有成员都用 kind，再只添加该命令需要的 title、id、query 或 path。

提示 2 · 让 case 完成收窄

进入 case "show" 后，command 已经是带 id 的 show 成员；直接返回 `show:${command.id}`，不要写 as。

提示 3 · 用 never 锁住默认分支

辅助函数参数与返回值都标注为 never，函数体抛错。default 中写 return assertNever(command)。

概念测验

判别联合的所有成员都已处理后，默认分支中的值是什么类型？

折叠完整答案与逐行解析

显示完整答案 
export type NoteCommand =
  | { kind: "add"; title: string }
  | { kind: "list" }
  | { kind: "show"; id: string }
  | { kind: "search"; query: string }
  | { kind: "archive"; id: string }
  | { kind: "import"; path: string }
  | { kind: "export"; path: string };

function assertNever(value: never): never {
  throw new Error(`Unexpected command: ${JSON.stringify(value)}`);
}

/** @lab */
export function describeCommand(command: NoteCommand): string {
  switch (command.kind) {
    case "add":
      return `add:${command.title}`;
    case "list":
      return "list";
    case "show":
      return `show:${command.id}`;
    case "search":
      return `search:${command.query}`;
    case "archive":
      return `archive:${command.id}`;
    case "import":
      return `import:${command.path}`;
    case "export":
      return `export:${command.path}`;
    default:
      return assertNever(command);
  }
}
第 1–8 行
七个对象成员共享 kind 字段；每个字面量 kind 与自己必需的 payload 绑定。
第 10–12 行
assertNever 只接受没有可能值的 never，并通过抛错保证返回类型也是 never。
第 14–30 行
switch 按 kind 收窄；每个 case 读取当前成员的独有字段并立即返回精确字符串。
第 31–32 行
全部成员处理后 command 是 never；新增成员而遗漏 case 时，这个调用会编译失败。
