对象有身份，集合选择应跟问题形状一致

数组不是 Java List 的换名，对象也不是轻量 JavaBean。你将从对象身份与引用开始，选择 Array、Map、Set，并用复制表达可观察的不可变更新。

前置回忆：参数复制引用值，共享对象仍可被修改

第 03 课已经看到：对象参数的引用值按值复制，调用者与函数内部仍可能指向同一对象。本课从这个事实继续：

export function demoSharedObject(): string {
  const note = { title: "Release", tags: ["typescript"] };
  const alias = note;

  alias.title = "Changed";
  return note.title; // "Changed"
}

note 与 alias 是两个绑定，但当前保存同一个对象引用。const 阻止重绑，不阻止经由引用修改对象。

详细心智模型：对象身份、集合语义与更新策略

1. 对象把属性键映射到值

普通对象最适合表达一个领域实体或一组有名字的字段。属性键通常是字符串或 symbol，读取方式有点号和方括号两种。点号适合源码中已知的合法标识符，方括号适合动态键。

export function readObjectProperties() {
  const title = "Release notes";
  const note = {
    title,
    status: "active",
    "created-at": "2026-08-20T08:00:00.000Z",
  };

  return {
    title: note.title,
    createdAt: note["created-at"],
  };
}

title 是属性简写，等价于 title: title。对象属性有顺序规则，但不应把普通对象当成专门的排序数据结构。

2. 数组是有序、按零开始索引的对象

数组适合有顺序、允许重复的同类值序列。length 表示索引范围上界相关的长度，不等同于 Java 集合的 size() 方法。访问不存在的索引在运行时返回 undefined，不会像 Java 一样立即抛越界异常。

export function inspectArrayIndexes() {
  const tags = ["typescript", "node"];

  return {
    first: tags[0],       // "typescript"
    missing: tags[9],     // undefined
    length: tags.length,  // 2
  };
}

本项目启用了 noUncheckedIndexedAccess，因此 TypeScript 会把普通索引读取视为“元素或 undefined”。这是静态层主动提醒你 JavaScript 的真实运行行为。

4. Map 表达任意键到值的映射

Map 的键可以是任意值，具有明确的 size、get、set、has 和迭代 API。它适合动态键集合、频繁增删或键并非普通字符串的情况。普通对象更适合固定字段的领域记录。

export function countTagsWithMap() {
  function countTags(tags: string[]) {
    const counts = new Map<string, number>();

    for (const tag of tags) {
      counts.set(tag, (counts.get(tag) ?? 0) + 1);
    }

    return counts.get("ts");
  }

  return countTags(["ts", "node", "ts"]);
}

get("ts") 在没有对应键时返回 undefined。这里省略显式返回类型，让 TypeScript 自己推断；number | undefined 的联合类型写法留到第 07 课。Map<string, number> 中的尖括号暂时只按“键是 string、值是 number”阅读，泛型机制会在第 09 课先讲解、再练习，本课 Lab 不要求书写这种语法。

5. Set 表达唯一值集合

Set 保证每个值最多出现一次，并保留插入迭代顺序。它适合去重和成员测试，不适合根据数字索引取第 N 项。

export function inspectUniqueTags() {
  function inspectTags(tags: string[]) {
    const uniqueTags = new Set(tags);

    return {
      size: uniqueTags.size,
      hasTypeScript: uniqueTags.has("ts"),
      values: [...uniqueTags],
    };
  }

  const tags = inspectTags(["ts", "node", "ts"]);
  const first = { id: "n1" };
  const second = { id: "n1" };
  const notes = new Set([first, second, first]);
  return { ...tags, objectCount: notes.size };
}

Set 去重只按值/身份，不做深比较

结果中的 objectCount 是 2：重复加入同一 first 引用会去重，内容相同的 second 仍是独立对象。按业务 id 去重时，应使用 Map 的 id 键或显式集合逻辑。

6. 展开语法按所在位置展开值

... 不是一个独立的“复制命令”。它放在哪里，决定了它要展开什么：

写法这里的 ... 做什么
[...source]依次读取可迭代值中的元素，把元素放进新数组。
{ ...source }读取对象自身可枚举属性，把属性名和属性值写进新对象。
fn(...source)把可迭代值中的元素依次作为函数参数。本课只需认识，不在 Lab 中使用。

6.1 先拆开数组展开

const copiedTags = [...original.tags, "node"] 可以按下面的顺序理解：

  1. 创建一个新的空数组。
  2. 依次读取 original.tags 中的元素，并放进新数组。
  3. 再把字符串 "node" 放到新数组末尾。

因此 copiedTags 和 original.tags 内容相似，但不是同一个数组。原数组没有被修改。

6.2 再拆开对象展开与覆盖顺序

{ ...original, tags: copiedTags } 会先创建新对象，再把 original 的属性写进去，最后用新的 tags 覆盖刚刚复制进来的旧 tags。对象字面量中，同名属性后写的值生效，所以顺序很重要。

export function demoTagCopy() {
  const original = {
    title: "Release",
    tags: ["typescript"],
  };

  const copiedTags = [...original.tags, "node"];
  const updated = {
    ...original,
    tags: copiedTags,
  };

  return {
    original,
    updated,
    sameObject: original === updated,
    sameTags: original.tags === updated.tags,
  };
}

这里的引用关系从 original → 外层对象 A → tags 数组 X，变成两条独立路径：original → A → X 和 updated → 外层对象 B → tags 数组 Y。所以返回结果中的 sameObject 和 sameTags 都是 false。

顺序不能反过来：{ tags: copiedTags, ...original } 会先写入新数组，再被后面的 original.tags 覆盖，结果仍然使用旧数组。

6.3 “浅复制”停在哪一层

展开语法只创建当前这一层的新容器，不会递归复制容器里面的对象或数组。若只写 { ...original }，外层对象虽然变了，但 tags 属性保存的仍是旧数组引用，因此 original.tags === updated.tags 会是 true。

本例修改路径是 note → tags，所以需要复制路径上的两层：用对象展开复制 note，再用数组展开复制 tags。如果某个嵌套值没有变化，就不必复制它。

本课先建立普通对象和数组的这个模型；原型、属性描述符、getter、symbol 键以及真正的深复制会在需要时单独讨论。

7. 不可变更新是可观察策略，不是 JavaScript 强制规则

JavaScript 允许修改；本课程在领域更新函数中优先返回新值，因为它减少别名之间的隐式影响，使测试、撤销、并发推理和状态比较更直接。局部、私有、短生命周期的可变变量仍然完全合理，例如在函数内部构建一个 Map。

选择标准：共享领域值用新值表达更新；函数内部受控的临时累积可以就地修改。不要为了“纯”而复制所有东西，也不要让调用者猜某个函数是否偷偷改了输入。

补充观察与运行

示例 A：转换、筛选与查找不要混在一个循环

export function selectActiveTitles(): string[] {
  const notes = [
    { title: "TypeScript", status: "active" },
    { title: "Old draft", status: "archived" },
  ];

  return notes
    .filter((note) => note.status === "active")
    .map((note) => note.title);
}

第一步回答“保留谁”，第二步回答“变成什么”。链式调用不是越多越好，但在两个清楚阶段时比同时维护索引与临时状态更易读。

示例 B：sort 会改原数组

export function sortTitles() {
  const titles = ["Zeta", "Alpha"];
  const sorted = [...titles].sort();

  return { titles, sorted };
}

先展开再排序，修改的是新数组。新运行时还提供 toSorted() 返回排序副本；这里展示展开是为了看清浅复制机制。

示例 C：浅复制仍可能共享嵌套数组

export function demoShallowCopy(): string[] {
  const original = { tags: ["ts"] };
  const shallow = { ...original };

  shallow.tags.push("node");
  return original.tags; // ["ts", "node"]
}

const shadow = original 只是把同一个对象引用交给另一个变量；shadow 只是变量名，换成前文的 alias 也没有区别。对象展开则会创建新的外层对象，但只复制各属性当前保存的值。对 tags 来说，这个值是数组引用，所以新旧外层对象仍指向同一个数组。

比较const shadow = originalconst shallow = { ...original }
外层对象同一个：original === shadow 为 true不同：original === shallow 为 false
内层 tags 数组同一个：original.tags === shadow.tags 为 true仍是同一个：original.tags === shallow.tags 为 true
other.tags.push("node")修改共享数组，original.tags 会变化同样修改共享数组，original.tags 也会变化
other.tags = ["node"]修改同一个外层对象的属性，original.tags 会变化只修改新外层对象的属性，original.tags 不变

因此当前示例使用 push 时，两种写法看起来结果相同；区别要在修改外层属性或重新给属性赋值时才会显现。引用关系分别是 original / shadow → 对象 A → 数组 X，以及 original → 对象 A → 数组 X、shallow → 对象 B → 数组 X。

记忆方式：直接赋值不复制任何对象；对象展开只复制当前这一层。更新嵌套集合时，要复制发生变化路径上的每一层。

常见误区

  1. 把 const 当深度不可变。 它只固定变量绑定，对象属性和数组仍可修改。
  2. 用 === 比较对象内容。 对象相等比较身份；结构断言需要深比较。
  3. 忘记 sort、reverse、push 等会修改原数组。 在共享领域值上先选择返回新数组的做法。
  4. 认为展开语法会深复制。 它只复制一层；嵌套引用默认共享。
  5. 所有键值数据都用普通对象。 动态任意键、频繁增删或需要明确 size 时 Map 更直接。
  6. 所有数组逻辑都用 reduce。 如果 filter + map 或清晰循环更能表达问题，就选更易读的方案。

addTag 必须按什么规则工作

  1. 读取传入的 tags 和 tag，不要修改原数组。
  2. 依次对 tag 执行 trim() 和 toLowerCase()，得到规范化标签。
  3. 创建新数组：先保留 tags 的全部元素和原顺序，再在末尾追加规范化标签。
  4. 返回这个新数组。

完成条件

  • 返回内容精确等于旧元素加规范化后的新标签。
  • updated !== tags：返回值必须是新数组。
  • 调用前后的输入 tags 内容完全相同；不要对它调用 push。
  • 函数内部不要打印内容；公开行为只有返回值。
本课不处理：标签去重和空标签拒绝策略。自动验收会传入非空标签；不要自行增加抛错、跳过追加等额外规则。

三层提示

提示 1 · 先规范化新标签

把 tag.trim().toLowerCase() 的结果保存到局部变量。字符串方法会返回新字符串，不会修改参数。

提示 2 · 构造新数组

数组表达式可以写成 [...tags, normalizedTag]；它会先展开旧元素，再追加新值。

提示 3 · 检查是否改了输入

函数只需要返回新数组，不需要调用 push，也不需要重新给输入变量赋值。验收会比较调用前后的原数组快照。

折叠完整答案与逐行解析

显示完整答案 
export function addTag(tags: string[], tag: string): string[] {
  const normalizedTag = tag.trim().toLowerCase();

  return [...tags, normalizedTag];
}
第 1 行
函数接收字符串数组和字符串，返回类型仍是字符串数组；这些都是前面课程已经使用过的类型标注。
第 2 行
先清理新标签并转成小写；原字符串没有被修改。
第 4 行
数组展开创建新数组，复制旧元素后追加新标签；输入数组保持原身份和原内容。
