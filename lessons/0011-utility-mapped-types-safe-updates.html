从一个真实对象契约派生视图，不复制第二份真相

列表摘要、局部更新和只读视图往往只是同一对象类型的不同形态。映射类型遍历已有键并转换属性修饰符；内置工具类型封装常见转换，让源类型变化时派生类型自动跟随。

前置回忆：第 10 课已经会遍历键的候选集合

export function demoKeyLookup(): string {
  type Note = {
    readonly id: string;
    title: string;
    archived: boolean;
  };
  type NoteKey = keyof Note;

  const key: NoteKey = "title";
  return key;
}

keyof Note 得到 "id" | "title" | "archived"。第 10 课用其中一个键读取 T[K]；本课改为让类型系统依次处理整个键联合，为每个键生成一个新属性声明。

详细心智模型：键联合进入映射，生成新的对象类型

1. 手写派生类型会产生两份容易漂移的契约

export function demoManualUpdateType(): { title?: string } {
  type Note = {
    readonly id: string;
    title: string;
    archived: boolean;
  };
  type ManualChanges = {
    title?: string;
    archived?: boolean;
  };

  const changes: ManualChanges = { title: "Release" };
  const note: Note = { id: "n1", title: "Draft", archived: false };
  void note;
  return changes;
}

ManualChanges 目前正确，但 Note 新增 body 或把 archived 改名后，它不会自动更新。类型别名不会在运行时同步；维护者必须记住修改两处。派生类型的目标是把 Note 留作唯一结构真相。

2. 映射类型逐个读取键和值类型

export function demoMappedOptional() {
  type NoteFields = {
    title: string;
    archived: boolean;
  };
  type OptionalFields<T> = {
    [Key in keyof T]?: T[Key];
  };

  const changes: OptionalFields<NoteFields> = { archived: true };
  const builtin: Partial<NoteFields> = { title: "Release" };
  return { mapped: changes, builtin };
}

keyof T 产生键联合；Key in ... 让 Key 依次代表每个成员；T[Key] 取回该属性原来的值类型；属性名后的问号把生成属性设为可选。最终仍是普通对象类型。

上面的 OptionalFields 是用于解释机制的手写版本；Partial 是同一规则的内置表达。mapped 与 builtin 都只能包含合法字段的任意子集。

Partial 是“全部属性可选”的内置映射

Partial 保留属性名和值类型，只改变可选性，所以 title 仍只能是 string。它允许任意子集，包括空对象；它不会创建对象、填充 undefined 或递归修改嵌套属性。

3. 把映射过程手动展开一次

  1. T 是 NoteFields，因此 keyof T 是 title | archived。
  2. Key 为 title 时，T[Key] 是 string，生成 title?: string。
  3. Key 为 archived 时，T[Key] 是 boolean，生成 archived?: boolean。
  4. 两个结果合并为一个对象类型；没有循环在 JavaScript 中执行。

映射类型是编译器构造类型的规则，不是 Array.map，也不会遍历运行时对象。

4. 映射修饰符可以增加或移除可选与只读

export function demoMappingModifiers(): {
  id: string;
  title: string;
} {
  type Draft = {
    readonly id: string;
    title?: string;
  };
  type MutableRequired<T> = {
    -readonly [Key in keyof T]-?: T[Key];
  };

  const complete: MutableRequired<Draft> = { id: "n1", title: "Draft" };
  complete.title = "Release";
  return complete;
}

-readonly 移除只读，-? 移除可选。没有前缀时 ? 与 readonly 等价于显式的 +? 与 +readonly。这些变化仍只影响静态属性契约。

5. Required 与 Readonly 转换相反维度

export function demoRequiredAndReadonly(): string {
  type Draft = {
    title: string;
    body?: string;
  };
  type CompleteDraft = Required<Draft>;

  const complete: Readonly<CompleteDraft> = {
    title: "Draft",
    body: "Details",
  };
  return complete.body;
}

Required 要求 body 必须出现；Readonly 阻止通过 complete 重新赋值 title 或 body。两者都是浅层类型转换：不会补值、冻结对象或递归处理嵌套对象。

6. Pick 选择键，Omit 排除键

export function demoPickAndOmit(): string {
  type Note = {
    readonly id: string;
    title: string;
    body?: string;
    archived: boolean;
  };
  type NotePreview = Pick<Note, "id" | "title">;
  type NewNote = Omit<Note, "id">;

  const preview: NotePreview = { id: "n1", title: "Draft" };
  const input: NewNote = { title: "Release", archived: false };
  return `${preview.title}:${input.title}`;
}

Pick 的第二个参数只能是 Note 的合法键；Omit 的第二个参数表示不保留的键。它们改变静态可见属性集合，不会在运行时从对象复制或删除字段。

7. Record 把一组固定键映射到统一值类型

export function demoRecord(): string {
  type NoteStatus = "active" | "archived";
  const labels: Record<NoteStatus, string> = {
    active: "Active",
    archived: "Archived",
  };

  return labels.active;
}

Record 要求 active 与 archived 都存在且值为 string。它适合“已知有限键集合到同一种值类型”的查找表；键各有不同值类型时，直接对象类型更清楚。

8. 组合工具类型建立更新面，再显式排除 id

export function demoSafeChanges(): string {
  type Note = {
    readonly id: string;
    title: string;
    archived: boolean;
  };
  type NoteChanges = Partial<Omit<Note, "id">> & {
    readonly id?: never;
  };

  const changes: NoteChanges = { title: "Release" };
  return changes.title ?? "Untitled";
}

先 Omit 移除 id，再 Partial 让剩余字段可选。交叉符号 & 要求同时满足右侧规则；在本项目的 exact optional 语义下，id?: never 表示 id 可以缺席，却没有合法值可写。这还能阻止带 id 的变量绕过额外属性检查。

9. 对象展开执行浅层、从左到右的运行时更新

export function demoShallowUpdate(): boolean[] {
  const metadata = { source: "cli" };
  const note = { id: "n1", title: "Draft", metadata };
  const updated = { ...note, title: "Release" };

  return [
    updated !== note,
    updated.title === "Release",
    note.title === "Draft",
    updated.metadata === metadata,
  ];
}

展开先复制 note 的自有可枚举属性，后面的 title 覆盖同名值。新外层对象与 note 不同，但未替换的 metadata 引用保持相同。类型工具不会改变这些 JavaScript 行为。

10. Lab 把静态更新面与原生展开连接起来

export function demoUpdateNote(): string {
  function updateNote<T extends { readonly id: string }>(
    note: T,
    changes: Partial<Omit<T, "id">> & { readonly id?: never },
  ): T {
    return { ...note, ...changes };
  }

  const note = { id: "n1", title: "Draft", archived: false };
  return updateNote(note, { title: "Release" }).title;
}
  1. 从 note 推断完整 T，并要求 T 至少有 readonly string id。
  2. Omit 从 T 的可更新面移除 id，Partial 让其余属性可选择提供。
  3. id?: never 明确拒绝任何试图更新 id 的对象或变量。
  4. 运行时展开 note，再用 changes 覆盖同名字段，返回同一 T 的新外层对象。
最小实现：工具类型只描述允许的 changes；JavaScript 对象展开已经实现浅层不可变更新，不需要更新器类、字段分派表或自定义循环。

补充观察与运行

示例 A：Readonly 是浅层约束

export function demoShallowReadonly(): number {
  const note: Readonly<{ metadata: { views: number } }> = {
    metadata: { views: 0 },
  };

  note.metadata.views += 1;
  return note.metadata.views;
}

不能把 note.metadata 重新赋给另一个对象，但嵌套对象本身没有被转成 Readonly，所以 views 仍可修改。需要深只读时必须有真实需求并明确递归规则；本课不创建通用 DeepReadonly。

示例 B：Required 不会在运行时填默认值

export function demoRequiredValue(): number {
  type Draft = { title?: string; limit?: number };
  type CompleteDraft = Required<Draft>;

  const complete: CompleteDraft = { title: "Draft", limit: 20 };
  return complete.limit;
}

Required 只要求赋值时提供两个属性。若输入来自 unknown，仍需运行时解析并主动设置默认值；类型工具不能把缺失字段变出来。

示例 C：Pick 不会投影运行时对象

export function demoPickDoesNotProject(): string[] {
  type Note = { id: string; title: string; archived: boolean };
  const note: Note = { id: "n1", title: "Draft", archived: false };
  const preview: Pick<Note, "id" | "title"> = note;

  return Object.keys(preview);
}

preview 的静态类型只暴露 id 与 title，但它仍引用原来的 note，运行时 Object.keys 仍得到 id、title、archived。真正投影数据需要显式创建新对象。

常见误区

  1. 手写一份与源类型几乎相同的更新类型。 源字段改变后副本会静默漂移。
  2. 把映射类型当成运行时循环。 它只构造静态类型，不读取或创建对象。
  3. 认为 Partial 把值类型加入 undefined。 在 exact optional 语义下，它表示属性可缺席，不表示可显式写 undefined。
  4. 认为 Required 会补齐数据。 它只收紧赋值契约，默认值仍要由运行时代码产生。
  5. 认为 Readonly 会冻结对象。 它是浅层静态限制，不等于 Object.freeze，更不是深冻结。
  6. 认为 Pick/Omit 会改变对象内容。 类型视图不会投影或删除运行时字段。
  7. 把 Record 用于值类型各不相同的对象。 直接对象类型通常更易读、更精确。
  8. 嵌套很多工具类型只为显得通用。 一个只用一次的简单对象类型往往更清楚。
  9. 把静态更新面当作外部数据校验。 JSON 或命令行输入仍应先作为 unknown 验证。
  10. 用对象展开更新类实例。 本课函数面向普通数据对象；展开不会保留原型与非枚举成员。

Learning Contract

进入条件类型、infer 与模板字面量类型前，你应当能够：

  • 把一个简单映射类型逐键展开，并写出最终对象类型。
  • 用映射修饰符增加或移除 readonly 与 optional。
  • 根据真实关系选择 Partial、Required、Readonly、Pick、Omit 或 Record。
  • 解释每个工具类型保留了什么、改变了什么，以及它没有执行什么运行时工作。
  • 组合 Partial<Omit<T, "id">> 建立非身份字段更新面。
  • 解释 id?: never 在 exact optional 语义下怎样拒绝 id。
  • 预测对象展开的覆盖顺序、外层身份与嵌套引用关系。
  • 知道何时停止类型组合并写一个直接对象类型。

Lab 11：安全地更新普通笔记对象

由你创建或修改：创建 src/lesson-11.ts，把本课案例、改写和 Lab 都保存在这里。

不要修改：tests/lessons.test.ts 与 scripts/；它们是课程验收工具。

你要交付什么

导出下面的泛型函数，面向至少具有 readonly string id 的普通数据对象：

updateNote<T extends { readonly id: string }>(
  note: T,
  changes: Partial<Omit<T, "id">> & { readonly id?: never },
): T

运行规则

  1. 返回 { ...note, ...changes } 创建的新外层对象。
  2. changes 中出现的属性覆盖 note 中的同名属性。
  3. 未更新属性保持原值；嵌套对象或数组保持原引用。
  4. 不修改 note、changes 或任何嵌套值。
  5. 空 changes 仍返回一个与 note 内容相等的新外层对象。

类型规则

  • T 必须保留调用方完整的普通对象类型，并至少包含 readonly string id。
  • changes 只允许 T 中除 id 外的属性；每个值必须匹配原属性类型。
  • 直接对象和先保存到变量的 changes 都不能包含 id。
  • 可选属性继续遵守 exact optional 语义，不能把缺失随意改写成显式 undefined。
  • 不要使用 any、unknown、类型断言、Object.assign、JSON 克隆、分支或自定义循环。

本课只处理已验证的普通数据对象。来自文件或网络的 unknown 仍需先验证；第 12 课才会解释 Omit 等工具内部使用的条件类型机制。

三层提示

提示 1 · 先写最小泛型约束

让 T extends 一个只含 readonly string id 的对象类型，这样完整的 title、archived、tags 等字段仍由调用方推断。

提示 2 · 先排除 id，再让其余字段可选

changes 的主体是 Partial<Omit<T, "id">>；再交叉 { readonly id?: never }，把 id 明确设为不可提供。

提示 3 · 运行时只需展开两次

先展开 note，再展开 changes。后出现的同名属性自然覆盖前值，并得到新外层对象。

折叠完整答案与逐行解析

显示完整答案 
export function updateNote<T extends { readonly id: string }>(
  note: T,
  changes: Partial<Omit<T, "id">> & { readonly id?: never },
): T {
  return { ...note, ...changes };
}
第 1 行
T 保留完整输入类型，同时要求普通笔记对象具有 readonly string id。
第 2 行
note 提供原始值，并决定本次调用的具体 T。
第 3 行
Omit 排除 id，Partial 让其余字段可选；id?: never 拒绝重新提供身份。
第 4 行
返回类型仍是 T，因此额外字段、readonly 与可选关系继续保留。
第 5 行
对象展开创建新外层对象，changes 从左到右覆盖同名属性。
第 6 行
函数结束；没有断言、分支、深克隆或额外状态。
