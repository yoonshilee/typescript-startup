空值必须进入类型，外部值必须先证明

null 与 undefined 是真实运行时值；unknown 则把“尚未知道”保留到边界检查之后。你将区分缺失、空值与未知输入，用 JavaScript 检查换取 TypeScript 中更精确的类型。

前置回忆：联合列出候选，检查排除不可能

第 07 课已经用 string | number 表示有限候选，并通过 typeof 收窄。空值也使用同一个模型：

export function demoNullableTitle(): string {
  function formatNullableTitle(title: string | null): string {
    if (title === null) {
      return "Untitled";
    }

    return title.trim();
  }

  return formatNullableTitle(null);
}

顶层案例函数无参数，固定输入写在函数内部，课程脚本可以直接执行它。内部 helper 的入口处 title 有两个候选；严格相等检查在运行时确认 null，返回后剩余路径只有 string。TypeScript 没有替你删除空值；它验证了你写出的 JavaScript 分支。

详细心智模型：缺失、未知与放弃检查不是一回事

1. null 与 undefined 是两个不同的原始值

值常见含义常见来源运行时观察
undefined未提供或未找到缺失属性、越界索引、无返回值typeof value === "undefined"
null调用方显式给出的空值协议字段、API 结果、手动赋值value === null

typeof null 的历史结果是 "object"，所以检查未知对象时必须先排除 null。不要因为二者都表示“没有可用内容”就把运行时值说成相同。

2. 严格空值检查让缺失进入联合

type NotePreview = {
  body?: string;
};

export function demoOptionalBody(): string {
  function describeOptionalBody(note: NotePreview): string {
    const body = note.body;

    if (body === undefined) {
      return "No body";
    }

    return `Body:${body}`;
  }

  return describeOptionalBody({});
}

项目启用了 strict，其中包含 strictNullChecks。读取可选属性时，body 的类型是 string | undefined；没有检查就调用字符串方法会报错。body?: string 描述属性可以不存在，不等于 body: string | undefined 描述属性一定存在但值可为 undefined。

3. exactOptionalPropertyTypes 保留“没有属性”

const withoutBody: NotePreview = {};
// const explicitUndefined: NotePreview = { body: undefined };
// 当前项目会拒绝上一行：可选属性没有声明显式 undefined。

JavaScript 中 "body" in withoutBody 是 false；而 { body: undefined } 的检查结果是 true。项目启用 exactOptionalPropertyTypes，因此类型也保留这个属性存在性的差异。

4. 索引访问也可能得到 undefined

export function demoFirstTitle(): string | undefined {
  function readFirstTitle(titles: string[]): string | undefined {
    return titles[0];
  }

  return readFirstTitle([]);
}

数组标注 string[] 约束已存在的元素，却不能证明索引 0 一定存在。项目启用 noUncheckedIndexedAccess，因此读取结果是 string | undefined。先检查长度也未必能被所有变更路径保持；直接处理读取结果最清楚。

5. ?? 只在 nullish 时使用默认值

export function demoDefaults() {
  function resolvePageSize(size: number | null | undefined): number {
    return size ?? 20;
  }

  const emptyTitle = "";
  return {
    zero: resolvePageSize(0),
    nullValue: resolvePageSize(null),
    missing: resolvePageSize(undefined),
    emptyTitle: emptyTitle ?? "Untitled",
  };
}

size ?? 20 只在 size 是 null 或 undefined 时返回 20。若 size 是 0，它仍返回 0。size || 20 会把 0、空字符串、false、NaN 也当成缺失；只有这些 falsy 值都确实无效时才应使用 ||。

对照四项结果：0、20、20、空字符串。只有 null 和 undefined 会触发右侧默认值。

空字符串不是 nullish

emptyTitle 已有空字符串值，因此不会采用 "Untitled"。若产品规则认为空白标题无效，应先明确调用 trim() 并检查结果，而不是把 ?? 换成含义更宽的 ||。

6. ?. 遇到 nullish 就停止当前链

export function demoOptionalBodyLength(): number {
  function getOptionalBodyLength(note: NotePreview | null): number {
    return note?.body?.length ?? 0;
  }

  return getOptionalBodyLength({ body: "Draft" });
}

若 note 是 null，第一次可选链返回 undefined；若 body 缺失，第二次可选链返回 undefined；最后 ?? 0 给出数字。可选链不会验证对象来自可信来源，也不会吞掉后续方法内部抛出的错误。

7. unknown 接受任何值，但禁止未经证明地使用

export function demoUnknownValue(): string {
  function formatUnknownValue(value: unknown): string {
    if (typeof value === "string") {
      return value.trim();
    }

    if (typeof value === "number") {
      return value.toFixed(0);
    }

    return "Unsupported";
  }

  return formatUnknownValue(7);
}

任何值都能赋给 unknown，但 unknown 不能直接赋给 string，也不能直接调用 trim()。每个运行时检查都提供新证据。unknown 适合文件内容、网络响应、用户输入和动态库返回值进入已建模代码的那一刻。

8. any 不是“更宽的 unknown”，而是关闭检查

function demoUnsafeTitleLength(): number {
  const value: any = { title: "Draft" };
  return value.title.trim().length;
}

这段代码对数字、null 或缺少 title 的对象都不会产生类型错误，却可能在运行时崩溃。any 还会沿属性读取继续传播。它适合受控迁移中的临时逃生口，不适合作为外部输入的默认类型；边界优先使用 unknown。

9. 信任边界必须把静态声明接到运行时事实

export function demoRawTitle(): string | undefined {
  function readRawTitle(value: unknown): string | undefined {
    if (value === null || typeof value !== "object" || !("title" in value)) {
      return undefined;
    }

    if (typeof value.title !== "string") {
      return undefined;
    }

    return value.title;
  }

  return readRawTitle({ title: "Release" });
}

检查顺序有运行时原因：先排除 null 和非对象，之后 in 才安全；确认属性存在后，属性值仍是 unknown；最后 typeof 才证明它是 string。整个过程没有 as，每一步都可在 JavaScript 中观察。

边界原则：类型标注不能净化数据。先把外部值收进 unknown，再用实际检查转换为内部类型；第 21 课会把这个单字段模式扩展成完整 API 数据校验。

Java 的 null 通常只有一个空值，而 JavaScript 生态同时保留 null 与 undefined。Python 的 Any 与 TypeScript any 都会削弱静态检查；TypeScript unknown 更像“允许传入任何值，但使用前必须证明”的安全入口。

补充观察与运行

示例 A：可选参数在函数体内包含 undefined

export function demoSearchLimit(): string {
  function formatSearchLimit(limit?: number): string {
    const resolvedLimit = limit ?? 20;
    return `Limit:${resolvedLimit}`;
  }

  return formatSearchLimit();
}

调用方可以省略参数；函数体内 limit 是 number | undefined。默认值表达式只负责选择值，不会改变原变量的运行时内容。

示例 B：把 JSON.parse 的结果立即收进 unknown

export function demoBoundaryJson(): unknown {
  function parseBoundaryJson(text: string): unknown {
    const value: unknown = JSON.parse(text);
    return value;
  }

  return parseBoundaryJson('{"title":"Draft"}');
}

标准库的 JSON.parse 返回 any；显式接到 unknown 后，调用方不能凭空读取属性。这里只建立边界，不在本课实现递归结构校验、错误路径或版本迁移。

示例 C：非空断言只消除诊断

function demoUnsafeFirstTitle(): string {
  function unsafeFirstTitle(titles: string[]): string {
    return titles[0]!.toUpperCase();
  }

  return unsafeFirstTitle([]);
}

! 告诉编译器“这里一定不是 null 或 undefined”，输出 JavaScript 时会被删除。空数组仍会在运行时读取 undefined 并调用方法。只有不变量已由别处可靠保证且无法被类型表达时才使用它。

常见误区

  1. 用 truthiness 代替空值检查。 0、空字符串和 false 可能是合法业务值。
  2. 认为可选属性等于显式 undefined。 当前配置会保留属性缺失与属性存在的差异。
  3. 把 optional chaining 当成数据校验。 它只在已知联合中短路 nullish，不证明陌生对象的结构。
  4. 给外部数据直接标注内部接口。 类型标注在运行时消失，错误对象不会自动被拒绝。
  5. 用 any 消除边界报错。 诊断消失的同时，后续属性链也失去保护。
  6. 用非空断言代替检查。 ! 不产生分支、不抛自定义错误，也不改变运行时值。
  7. 把 never 与 unknown 混为一谈。 unknown 可能是任何值；never 表示没有任何可能值。

Learning Contract

进入函数类型与泛型前，你应当能够：

  • 分别说明 null、undefined 在运行时的来源与检查方法。
  • 从可选属性、可选参数和索引访问预测 undefined 联合。
  • 根据 0、空字符串、false、null、undefined 预测 ?? 与 || 的不同结果。
  • 使用 optional chaining 读取已建模的可空路径，并处理最终 undefined。
  • 把不可信输入标成 unknown，按安全顺序检查 null、object、属性存在性与属性值类型。
  • 解释 any、类型断言与非空断言为什么不会提供运行时证据。

Lab 08：从 unknown 边界读取可选笔记标题

由你创建或修改：创建 src/lesson-08.ts，把本课示例、改写和 Lab 都保存在这里。

不要修改：tests/lessons.test.ts 与 scripts/；它们是课程验收工具。

你要交付什么

导出 readNoteTitle(value: unknown): string | undefined。它只接受一个未知值，不导出额外类型或辅助函数。

边界规则

  1. 只有非 null 的 object 才能继续检查；数组也属于 object，但没有合格 title 时会自然失败。
  2. 对象必须存在 title 属性，且属性值必须是 string。
  3. 对字符串调用 trim()；清理后非空就返回清理结果。
  4. 其他所有输入都返回 undefined，包括 null、undefined、原始字符串、缺属性对象、非字符串 title 与纯空白 title。

完成条件

  • 参数保持 unknown，不能改成 any。
  • 属性读取前完成 null、object 与属性存在性检查。
  • 不使用 as 或非空断言。
  • 返回类型精确为 string | undefined，调用方必须处理缺失。

本课只读取一个字段并折叠失败为 undefined，不解析完整 Note、不收集错误路径、不处理版本。结构化运行时校验留到第 21 课。

三层提示

提示 1 · 先证明可以使用 in

把 null、typeof value !== "object" 和 !("title" in value) 放进一个提前返回条件。短路求值保证只有对象才执行 in。

提示 2 · 属性存在后仍是 unknown

用 typeof value.title !== "string" 再次提前返回。通过该分支后，value.title 才能安全调用 trim。

提示 3 · 清理后处理空字符串

保存 const title = value.title.trim()；如果 title 等于空字符串就返回 undefined，否则返回 title。

概念测验

为什么接收 unknown 的值后必须先收窄？

折叠完整答案与逐行解析

显示完整答案 
export function readNoteTitle(value: unknown): string | undefined {
  if (value === null || typeof value !== "object" || !("title" in value)) {
    return undefined;
  }

  if (typeof value.title !== "string") {
    return undefined;
  }

  const title = value.title.trim();
  return title === "" ? undefined : title;
}
第 1 行
unknown 接收任意边界值，但返回联合把缺失继续暴露给调用方。
第 2–4 行
短路条件先排除 null 与非对象，再安全执行属性存在性检查。
第 6–8 行
title 属性存在仍不代表值是字符串；typeof 提供调用 trim 所需的运行时证据。
第 10–11 行
清理字符串并把纯空白标题归一为 undefined；合法标题返回清理结果。
