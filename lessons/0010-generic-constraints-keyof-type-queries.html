先限制合法能力，再从已有类型读取答案

无约束的泛型可以代表任何类型，所以不能假设它有某个属性。约束缩小合法输入范围；keyof 读取合法属性键，索引访问类型读取属性值类型，typeof 则把已有值的静态类型带进类型位置。

本课代码文件：创建 src/lesson-10.ts，可运行案例使用导出的无参函数；带参数 helper 放在案例内部；Lab 由课程 HTML 自动识别，无需特殊注释。

任务卡

完成物：实现 getProperty<T, K extends keyof T>(value, key): T[K]，让键只能来自对象，并让返回类型随所选属性变化。

  • 理解无约束泛型为什么不能随意访问属性。
  • 用 extends 描述所有合法输入都必须具备的最小结构。
  • 用 keyof 从对象类型得到属性键联合。
  • 用 T[K] 从键反查对应属性值类型。
  • 用 typeof、keyof typeof 与 (typeof values)[number] 从现有值派生类型。

前置回忆：普通泛型只保存类型关系

export function demoGenericIdentity(): { id: string; title: string } {
  function identity<T>(value: T): T {
    return value;
  }

  return identity({ id: "n1", title: "Draft" });
}

第 09 课的 T 可以是 string、number 或任意对象。编译器因此只知道“输入和输出是同一个 T”，不知道每个 T 都有 id。要读取属性，必须先证明该属性存在，或让属性键本身受 T 约束。

详细心智模型：值、键与属性类型形成一条链

1. 无约束 T 必须按“可能是任何类型”使用

export function demoUnconstrainedGeneric(): string {
  function describe<T>(value: T): string {
    return String(value);
  }

  return describe({ id: "n1", title: "Draft" });
}

describe 能把 value 交给接受任意值的 String，但不能直接写 value.id：T 也可能是 number。泛型不是“编译器暂时不知道但我知道”，而是函数必须对声明允许的每一种 T 都成立。

2. 泛型约束声明所有合法 T 的最小能力

export function demoIdConstraint(): string {
  function readId<T extends { id: string }>(value: T): string {
    return value.id;
  }

  return readId({ id: "n1", title: "Draft" });
}

T extends { id: string } 不表示类继承；它表示 T 至少要满足这个结构。对象仍可保留 title 等额外属性，函数体则能安全读取 string 类型的 id。约束是准入条件，不会把完整 T 缩成只有 id 的对象。

3. keyof 把对象类型的属性名读成联合类型

export function demoKeyof() {
  type NoteSnapshot = {
    readonly id: string;
    title: string;
    archived: boolean;
  };
  type NoteKey = keyof NoteSnapshot;

  type SummaryValue = NoteSnapshot["title" | "archived"];
  const values: SummaryValue[] = ["Draft", false];
  const key: NoteKey = "title";
  return { key, values };
}

这里 NoteKey 是 "id" | "title" | "archived"。它存在于类型检查阶段，没有在运行时创建键数组；把 "missing" 赋给 NoteKey 会报错。

T[K] 是索引访问类型，不是一次运行时取值

NoteSnapshot["title"] 是 string；用键联合索引时，结果是这些属性值的联合，所以 SummaryValue 是 string | boolean。方括号出现在类型位置时读取类型，出现在 value[key] 中时才读取运行时值。

4. K extends keyof T 把第二个参数限制为第一个参数的键

export function demoGenericProperty(): string {
  function getProperty<T, K extends keyof T>(
    value: T,
    key: K,
  ): T[K] {
    return value[key];
  }

  const note = { id: "n1", title: "Draft", archived: false };
  const title = getProperty(note, "title");
  const archived = getProperty(note, "archived");
  return `${title}:${archived}`;
}

调用时先从 note 推断 T，再计算 keyof T，最后要求 K 是其中一个成员。传 title 时 K 是 "title"；传 missing 时不满足约束，错误在调用点出现。

Lab 的编译期推导与运行时只发生一次属性读取

  1. 编译器从 note 得到 T：包含 string title 与 boolean archived。
  2. 第一次调用把 K 推断为 title，所以 T[K] 是 string。
  3. 第二次调用把 K 推断为 archived，所以 T[K] 是 boolean。
  4. 编译后泛型、keyof 与 T[K] 都被擦除，函数体只剩 return value[key]。
最小实现：JavaScript 的方括号访问已经完成全部运行时工作。Lab 只需要用类型参数描述“这个键属于这个对象，返回值属于这个键”。

5. 可选属性的索引访问结果保留 undefined

export function demoOptionalIndexedAccess(): string | undefined {
  type DraftNote = {
    title: string;
    body?: string;
  };
  type Body = DraftNote["body"];

  const body: Body = undefined;
  return body;
}

body 可能不存在，因此读取它的结果是 string | undefined。T[K] 不会替你消除缺失状态；调用方仍需像第 08 课那样收窄 undefined。

6. 类型位置的 typeof 读取标识符的静态类型

export function demoTypeQuery(): {
  status: string;
  limit: number;
} {
  const defaultOptions = {
    status: "active",
    limit: 20,
  };
  type ListOptions = typeof defaultOptions;

  const copied: ListOptions = { ...defaultOptions };
  return copied;
}

运行时表达式 typeof defaultOptions 会得到字符串 "object"；类型位置的 type ListOptions = typeof defaultOptions 则读取编译器已经推断出的对象类型。两者拼写相同，执行阶段不同。

7. keyof typeof 从一个值派生可用键

export function demoValueDerivedKeys(): string {
  const statusLabels = {
    active: "Active",
    archived: "Archived",
  } as const;
  type Status = keyof typeof statusLabels;

  function labelStatus(status: Status): string {
    return statusLabels[status];
  }

  return labelStatus("active");
}

先用 typeof 得到 statusLabels 的对象类型，再用 keyof 得到 "active" | "archived"。常量是运行时真相，类型从它派生；增加一个标签后，Status 会自动跟随。

8. (typeof array)[number] 读取数组元素类型

export function demoArrayElementType(): string {
  const noteSeeds = [
    { id: "n1", title: "Draft" },
    { id: "n2", title: "Release" },
  ] as const;
  type NoteSeed = (typeof noteSeeds)[number];

  const first: NoteSeed = noteSeeds[0];
  return first.title;
}

typeof 先取得只读元组类型，[number] 再表示“用任意数字索引可能得到的元素”。结果是两个元素类型的联合，不需要手写一份可能与数据漂移的 NoteSeed。

TypeScript 特别擅长描述 JavaScript 已有的动态属性访问：运行时仍是普通 value[key]，类型系统则在编译前证明 key 合法并算出结果类型。它不是 Java 反射，也不会在运行时查询类型元数据。

补充观察与运行

示例 A：一次读取多个合法键

export function demoKeyUnion(): string[] {
  function getProperties<T, K extends keyof T>(
    value: T,
    keys: readonly K[],
  ): T[K][] {
    return keys.map((key) => value[key]);
  }

  const note = { id: "n1", title: "Draft", archived: false };
  return getProperties(note, ["id", "title"]);
}

K 推断为 "id" | "title"，所以 T[K][] 是 string[]。若 keys 同时包含 archived，返回类型会诚实地变成 Array<string | boolean>。

示例 B：Object.keys 是运行时字符串数组

export function demoObjectKeys(): string[] {
  const note = { id: "n1", title: "Draft" };
  return Object.keys(note);
}

Object.keys 枚举运行时自有可枚举字符串键，标准声明保守地返回 string[]，不会自动成为 Array<keyof typeof note>。本课不靠类型断言把它强行变窄；已知键应直接由受约束参数传入。

示例 C：约束允许额外属性且保留完整 T

export function demoPreservedType(): boolean {
  function keepValue<T extends { id: string }>(value: T): T {
    return value;
  }

  const note = keepValue({ id: "n1", archived: false });
  return note.archived;
}

约束只要求 id，不会丢掉 archived。若把参数和返回类型直接写成 { id: string }，调用合法但返回值类型只承诺 id；泛型 T 才保存了完整输入类型。

常见误区

  1. 把 extends 一律理解成类继承。 泛型约束通常只要求结构兼容，不创建继承关系。
  2. 约束写得比函数实际需要更大。 只读取 id 就只要求 id；额外字段会排除本来合法的调用。
  3. 把 keyof 当成 Object.keys。 前者产生编译期键类型，后者返回运行时 string[]。
  4. 写成 key: string。 任意 string 未必属于 T，返回值也无法保持所选属性的精确关系。
  5. 把 T[K] 当成运行时表达式。 它只在类型位置成立，运行时读取仍需 value[key]。
  6. 忽略可选属性。 可选属性的索引访问结果包含 undefined，不能直接当 string 使用。
  7. 混淆两种 typeof。 表达式里的 typeof 返回运行时字符串；类型位置的 typeof 读取静态类型。
  8. 把类型约束当作数据校验。 类型会被擦除；来自 JSON、网络或命令行的 unknown 仍需第 08 课式运行时检查。
  9. 用 any 或类型断言压掉非法键错误。 这会移除 Lab 要建立的对象、键与返回值关系。

Learning Contract

进入工具类型与映射类型前，你应当能够：

  • 解释为什么无约束 T 不能假设具有某个属性。
  • 写出最小结构约束，并说明它不会抹掉 T 的额外属性。
  • 把 keyof T 展开成具体属性键联合。
  • 根据 K 计算 T[K]，包括键联合与可选属性的结果。
  • 区分类型位置和表达式位置的方括号与 typeof。
  • 用 keyof typeof 从对象常量派生键，用 (typeof values)[number] 派生元素类型。
  • 说明这些类型操作会被擦除，不能替代外部数据的运行时校验。

Lab 10：读取合法属性并保留精确类型

你要交付什么

导出下面的泛型函数，并保持对象、键和返回类型的关系：

getProperty<T, K extends keyof T>(
  value: T,
  key: K,
): T[K]

运行规则

  1. 使用方括号读取并返回 value[key]。
  2. 字符串、布尔值、数组和对象属性都应原样返回。
  3. 属性值是对象或数组时，保留原引用，不复制。
  4. 不修改 value，也不枚举、添加或删除属性。

类型规则

  • 只使用 T 与 K 两个类型参数，K 必须写成 K extends keyof T。
  • 返回类型必须是 T[K]，不能拓宽成 T[keyof T]、unknown 或 any。
  • 普通对象、readonly 对象、数字数组索引和可选属性都要保留各自推断结果。
  • 不存在的键必须在编译期被拒绝。
  • 不要加入重载、类型断言、运行时校验、默认值、克隆或异常处理。

本课只训练从已有类型查询信息。第 11 课会用工具类型和映射类型批量转换对象属性。

三层提示

提示 1 · 先连接对象类型与键类型

声明 T 后，再声明 K extends keyof T。这样 key: K 不能离开 value 的属性集合。

提示 2 · 用同一对类型参数表达返回值

返回类型不是联合所有属性，也不是 unknown；写 T[K]，它会随每次调用选择的 K 改变。

提示 3 · 运行时只需原生方括号访问

函数体直接 return value[key];。合法性和结果类型已由签名表达，不需要 if、Object.keys 或类型断言。

概念测验

在 getProperty<T, K extends keyof T> 中，T[K] 表示什么？

折叠完整答案与逐行解析

显示完整答案 
export function getProperty<T, K extends keyof T>(
  value: T,
  key: K,
): T[K] {
  return value[key];
}
第 1 行
T 保存完整对象类型；K 只能是 keyof T 中的合法属性键。
第 2–3 行
value 提供对象类型，key 提供本次调用选择的具体键类型。
第 4 行
T[K] 查询该键在该对象类型中对应的属性值类型。
第 5 行
运行时使用原生方括号访问，直接返回属性值并保留引用身份。
第 6 行
函数结束；没有断言、分支、克隆或额外状态。
