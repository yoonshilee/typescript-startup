控制流决定路径，函数组织可复用步骤

本课继续建立语法手感：用条件和循环选择路径，把函数当作值传递或返回。返回函数为什么能继续使用外层变量，留到第 13 课结合 JavaScript 与 Node 的执行模型解释。

本课代码文件：把所有 TypeScript 练习依次放入 src/lesson-03.ts。可运行案例使用导出的无参函数；带参数 helper 放在案例内部；Lab 由课程 HTML 自动识别，无需特殊注释。

前置回忆：表达式先产生值，控制流再选择是否使用

第 02 课中，比较表达式会产生 boolean，任意值进入条件位置还会按照 truthiness 转换。本课不改变这条规则，只是在它上面建立路径：

export function demoTitleAcceptance(): string {
  function describeTitleAcceptance(title: string): string {
    const hasTitle = title.trim().length > 0;

    if (hasTitle) {
      return "Title accepted.";
    }

    return "Title rejected.";
  }

  return describeTitleAcceptance("Release notes");
}

外层案例保存固定调试输入；内部 helper 的 hasTitle 保存一个 boolean 值，if 根据它决定是否进入花括号中的分支。

详细心智模型：路径、重复与返回函数

1. 条件语句选择路径，尽早返回减少嵌套

if、else if 和 else 从上到下检查条件，只执行第一个匹配分支。函数中遇到 return 会立即结束当前调用并把值交回调用者。对无效输入尽早返回，通常比把主要逻辑包在多层条件里更容易读。

export function demoLimit(): string {
  function describeLimit(limit: number): string {
    if (!Number.isFinite(limit) || limit < 0) {
      return "invalid";
    }

    if (limit === 0) {
      return "none";
    }

    return "positive";
  }

  return describeLimit(1);
}

三个返回路径互斥。执行到最后一行已经隐含“有限、非负且不为零”，所以不必重复条件。

2. 循环重复执行，但循环形式应表达意图

for...of 直接遍历可迭代值，适合数组、字符串、Map 和 Set；经典 for 适合确实需要索引或步长；while 适合次数事先未知、由条件推进的过程。for...in 遍历对象的可枚举键，不是数组值循环的默认选择。

export function demoTagLoop(): string[] {
  function uppercaseTagsWithLoop(tags: string[]): string[] {
    const uppercaseTags: string[] = [];

    for (const tag of tags) {
      uppercaseTags.push(tag.toUpperCase());
    }

    return uppercaseTags;
  }

  return uppercaseTagsWithLoop(["typescript", "node", "cli"]);
}

循环体每次获得一个新的块级 tag 绑定。只有需要提前结束时才使用 break，只跳过当前项时使用 continue；普通映射和筛选在第 04 课用数组方法表达会更直接。

3. 函数既是可调用代码，也是普通值

TypeScript 函数可以放入变量、作为参数传入，也可以作为返回值返回。函数类型描述它接收什么、返回什么。

export function demoFunctionAlias(): string {
  function normalize(value: string): string {
    return value.trim().toLowerCase();
  }

  const normalizeAgain = normalize;
  return normalizeAgain(" TypeScript ");
}

函数声明适合表达主要动作；箭头函数适合短回调和返回函数。本课只比较写法，不展开 this 等内部差异。

4. 返回函数把一次配置变成可重复步骤

export function demoPrefixes(): string[] {
  function withPrefix(prefix: string): (value: string) => string {
    return (value: string): string => `${prefix}:${value}`;
  }

  const labelCourse = withPrefix("course");
  const labelProject = withPrefix("project");
  return [labelCourse("typescript"), labelProject("cli")];
}

先按语法读：外层函数接收 prefix，返回一个“接收字符串并返回字符串”的函数；返回的箭头函数使用 prefix 与自己的 value。为什么外层调用结束后仍能使用 prefix，将在第 13 课解释。

两个配置产生两个处理函数

两次调用分别返回函数。现在只观察它们拥有不同配置和输出；内部保存机制留到第 13 课。

本课边界：会写、会调用、会读函数类型即可；暂时不需要画调用帧或词法环境。

补充观察与运行

示例 A：for...of 与 for...in 回答不同问题

export function compareArrayIteration() {
  function collectIteration(tags: string[]) {
    const values: string[] = [];
    const keys: string[] = [];

    for (const tag of tags) {
      values.push(tag);
    }

    for (const key in tags) {
      keys.push(key);
    }

    return { values, keys };
  }

  return collectIteration(["ts", "node"]);
}

前者遍历数组值，后者遍历可枚举属性键。需要数组值时默认选择 for...of。参数属于内部 helper，外层案例负责传入固定数组。

示例 B：箭头函数直接返回对象时需要圆括号

export function demoArrowObject() {
  const makeNote = (value: string) => ({
    title: value,
    status: "active",
  });

  return makeNote("TypeScript");
}

箭头函数直接返回对象时，圆括号告诉解析器花括号是对象字面量，不是函数体。去掉圆括号会得到完全不同的解析结果。

常见误区

  1. 把 for...in 当成 Java 增强 for。 数组值遍历使用 for...of。
  2. 所有分支都写 else。 已经 return 的防卫分支之后，主路径无需再嵌套。
  3. 看见 () => string 就把它当成调用。 这是函数类型；真正调用需要在函数值后写 ()。
  4. 箭头函数返回对象时忘记圆括号。 () => ({ ... }) 才是直接返回对象字面量。
  5. 在循环里修改正在遍历的集合。 可能跳项或产生难以预测的路径；先构造新结果通常更清晰。
  6. 为了短而堆叠三元表达式。 多分支业务路径用具名函数和清晰 if 更容易验证。

任务

实现 createTagNormalizer(prefix: string): (tag: string) => string。

  • 外层函数先把前缀执行 trim() 与 toLowerCase()。
  • 返回的函数把传入 tag 同样清理并转小写。
  • 用冒号连接：createTagNormalizer(" Course ")(" TypeScript ") 返回 "course:typescript"。
  • 不同 normalizer 必须记住各自前缀；函数不能打印或修改参数。

这不是为了少写一次 trim()，而是为了练习“一次配置，生成一个处理函数”的代码形状。它为什么有效，第 13 课会再展开。

折叠完整答案与逐行解析

显示完整答案 
export function createTagNormalizer(
  prefix: string,
): (tag: string) => string {
  const normalizedPrefix = prefix.trim().toLowerCase();

  return (tag: string): string =>
    `${normalizedPrefix}:${tag.trim().toLowerCase()}`;
}
第 1–3 行
外层函数接受 string，并承诺返回另一个“string 到 string”的函数。
第 4 行
外层函数先创建规范化后的前缀。
第 5 行
空行分隔配置阶段与返回行为，不影响运行。
第 6–7 行
返回的箭头函数清理 tag，并使用 normalizedPrefix 组合结果。
第 8 行
右花括号结束外层函数；变量保存机制留到第 13 课解释。
