让输入类型决定输出类型，同时保持运行时实现诚实

条件类型根据可赋值关系选择结果，infer 从匹配结构中提取类型，模板字面量类型把字符串字面量组合成新协议。三者共同表达“输入结构变化，输出类型随之变化”，但都不会生成运行时代码。

本课代码文件：创建 src/lesson-12.ts，可运行案例使用导出的无参函数；带参数 helper 放在案例内部；Lab 由课程 HTML 自动识别，无需特殊注释。

任务卡

完成物：从命令对象联合中提取 kind 字面量，派生对应的 note:kind 事件名类型，并实现保留输入字面量的 createNoteEvent(kind)。

  • 读懂 T extends U ? X : Y 的可赋值判断与两个结果分支。
  • 使用 infer 命名数组元素、函数返回值或对象属性中的类型。
  • 预测裸类型参数遇到联合类型时的分布行为。
  • 用方括号阻止分布，比较“逐个成员判断”与“整体判断”。
  • 用模板字面量类型组合有限字符串协议，并与运行时模板字符串分开理解。

时间预算：模型与实验 60 分钟，Lab 25 分钟，复盘 10 分钟。

前置回忆：第 10 课已经会从已知键读取类型

export function demoIndexedAccess(): string {
  type Note = {
    readonly id: string;
    title: string;
  };
  type Title = Note["title"];

  const title: Title = "Draft";
  return title;
}

索引访问要求先知道要读哪个键。现在的问题更一般：输入可能是数组、函数、带 kind 的对象或完全不同的结构。条件类型先判断结构是否匹配；匹配时 infer 可以直接给其中某一部分命名。

详细心智模型：在类型层匹配结构、提取部分、组合结果

1. 条件类型选择的是类型结果，不是运行时代码

export function demoConditionalBranch(): string[] {
  type Category<T> = T extends string ? "text" : "other";
  type TitleCategory = Category<string>;
  type CountCategory = Category<number>;

  const titleCategory: TitleCategory = "text";
  const countCategory: CountCategory = "other";
  return [titleCategory, countCategory];
}

编译器检查 string 是否可赋给 string，选择 "text"；number 不可赋给 string，选择 "other"。JavaScript 运行时只看到数组和值，不会执行一次隐藏的 if。

2. extends 表示可赋值关系，不表示类继承

export function demoStructuralMatch(): boolean[] {
  type HasStringId<T> =
    T extends { readonly id: string } ? true : false;
  type NoteMatch = HasStringId<{ id: string; title: string }>;
  type CountMatch = HasStringId<{ id: number }>;

  const noteMatch: NoteMatch = true;
  const countMatch: CountMatch = false;
  return [noteMatch, countMatch];
}

第一个对象即使没有 implements 或父类，也拥有兼容的 string id，所以匹配成功。这里比较的是结构可赋值性；不要把它翻译成 Java 的 extends 或 Python 的子类检查。

3. 把约束放进条件，允许不匹配输入得到 never

export function demoConditionalConstraint(): string {
  type MessageOf<T> =
    T extends { message: unknown } ? T["message"] : never;
  type ErrorMessage = MessageOf<{ message: string }>;
  type MissingMessage = MessageOf<{ code: number }>;

  const message: ErrorMessage = "Not found";
  type MissingMessageIsNever = MissingMessage extends never ? true : false;
  const missingMessageIsNever: MissingMessageIsNever = true;
  void missingMessageIsNever;
  return message;
}

若把 T extends { message: unknown } 写在泛型参数处，不含 message 的类型会在使用别名时直接报错。把检查移入条件后，所有 T 都能进入；匹配分支读取 T["message"]，不匹配分支得到 never。

4. infer 在匹配位置声明一个待推断类型变量

export function demoArrayElementInference(): string {
  type ElementOf<T> =
    T extends readonly (infer Item)[] ? Item : never;
  type Title = ElementOf<readonly string[]>;
  type Count = ElementOf<number[]>;

  const title: Title = "Draft";
  const count: Count = 2;
  return `${title}:${count}`;
}

匹配 readonly 数组结构时，infer Item 表示“把这里出现的元素类型命名为 Item”。string[] 得到 string，number[] 得到 number；非数组进入 never 分支。infer 只能出现在条件类型的 extends 子句中。

5. 同一模式可以提取函数返回类型

export function demoReturnInference(): string {
  type OutputOf<T> =
    T extends (...args: never[]) => infer Output ? Output : never;

  function createSummary() {
    return { count: 2, active: true };
  }

  const summary: OutputOf<typeof createSummary> = createSummary();
  return `${summary.count}:${summary.active}`;
}

typeof 先取得 createSummary 的函数类型，条件类型再匹配其返回位置并命名为 Output。内置 ReturnType 使用相同方向的思想；真实代码优先使用内置工具，自己写这个别名是为了看清机制。

6. 裸类型参数遇到联合时会逐成员分布

export function demoDistribution() {
  type ToArray<T> = T extends unknown ? T[] : never;
  type ToArrayTogether<T> = [T] extends [unknown] ? T[] : never;
  type SeparateArrays = ToArray<string | number>;
  type MixedArray = ToArrayTogether<string | number>;

  const separate: SeparateArrays = ["Draft"];
  const mixed: MixedArray = ["Draft", 2];
  // const invalid: SeparateArrays = ["Draft", 2]; // Mixed elements are rejected.
  return { separate, mixed };
}
  1. 输入是 string | number，T 在 extends 左侧保持裸露。
  2. 编译器分别计算 ToArray<string> 与 ToArray<number>。
  3. 结果重新联合为 string[] | number[]，不是 (string | number)[]。

方括号让联合整体参与一次判断

对照同一代码块中的 ToArrayTogether：[T] extends [unknown] 的左右两侧都包成单元素元组，T 不再是裸类型参数，因此只判断一次，结果是 (string | number)[]。所以 separate 只能装同一类元素，mixed 可以同时装字符串与数字。方括号在这里是类型语法，不会创建运行时数组。

7. never 会从联合中消失，因此条件类型可以筛选联合

export function demoUnionFilter(): string {
  type StringsOnly<T> = T extends string ? T : never;
  type CommandKind = StringsOnly<"add" | 404 | "list">;

  const kind: CommandKind = "list";
  return kind;
}

分布后得到 "add" | never | "list"；never 没有可取值成员，合并时消失，留下两个字符串字面量。内置 Exclude 与 Extract 就利用了这种模式。

8. 模板字面量类型组合字符串字面量联合

export function demoTemplateLiteralUnion(): string[] {
  type Action = "add" | "list";
  type EventName = `note:${Action}`;

  const events: EventName[] = ["note:add", "note:list"];
  return events;
}

模板中的 Action 是两个成员，因此 EventName 展开为 "note:add" | "note:list"。若有多个联合插值位置，编译器会生成所有组合；成员很多时应改用普通 string 和运行时校验，避免难读的大联合。

9. infer 与模板字面量类型可以串成一条派生链

export function demoEventDerivation(): string {
  type KindOf<T> =
    T extends { readonly kind: infer Kind extends string }
      ? Kind
      : never;
  type NoteEvent<T> = `note:${KindOf<T>}`;
  type Command =
    | { kind: "add"; title: string }
    | { kind: "list" };

  const event: NoteEvent<Command> = "note:add";
  return event;
}

Command 联合先分布；每个成员匹配 readonly kind 并推断受 string 约束的 Kind；两个字面量再进入模板，得到 "note:add" | "note:list"。源命令新增字面量成员时，事件类型自动跟随。

10. 运行时仍要由普通 JavaScript 创建字符串

export function demoRuntimeTemplate(): string {
  function createEvent<Kind extends string>(
    kind: Kind,
  ): `note:${Kind}` {
    return `note:${kind}`;
  }

  return createEvent("add");
}

类型签名保留输入字面量与输出字面量的关系，函数体中的模板字符串才真正创建字符。Kind、条件类型和模板字面量类型都会擦除；编译后不会验证外部字符串是否符合事件协议。

最小实现：类型层只表达输入与输出关系，运行时只用一个模板字符串。这里不需要事件类、注册表、类型断言或递归字符串解析器。

补充观察与运行

示例 A：优先使用内置 Exclude 与 Extract

export function demoExcludeAndExtract(): string[] {
  type Command = "add" | "list" | "archive";
  type Writable = Exclude<Command, "list">;
  type ReadOnly = Extract<Command, "list" | "show">;

  const writable: Writable = "archive";
  const readOnly: ReadOnly = "list";
  return [writable, readOnly];
}

Exclude 删除可赋给第二个参数的成员；Extract 只保留可赋给第二个参数的成员。它们已经清楚表达意图时，不要再包装一层自定义条件类型。

示例 B：内置字符串转换类型仍只存在于类型层

export function demoUppercaseEvent(): string {
  type Action = "add" | "list";
  type MetricName = `NOTE_${Uppercase<Action>}`;

  const metric: MetricName = "NOTE_ADD";
  return metric;
}

Uppercase 把字面量成员转换为大写类型。它不会调用字符串的 toUpperCase，也不会改变变量里的值；需要转换运行时输入时仍要显式执行 JavaScript。

示例 C：宽 string 会让模板结果保持开放

export function demoWideStringEvent(): string {
  type EventName = `note:${string}`;
  const event: EventName = "note:custom";
  return event;
}

EventName 不是有限枚举，而是所有以 note: 开头的字符串。模板字面量类型能约束形状，但不能枚举无限输入，也不会在运行时解析或验证前缀。

常见误区

  1. 把条件类型当成运行时 if。 它选择类型结果，不读取变量值。
  2. 把 extends 理解成类继承。 条件类型判断结构可赋值性。
  3. 在条件外约束 T，却又期待不匹配输入得到 never。 外部约束会先拒绝调用。
  4. 把 infer 当成任意位置可用的声明。 它只能在条件类型的 extends 匹配结构中出现。
  5. 忘记裸类型参数会分布。 string | number 可能得到两个数组的联合，而不是混合数组。
  6. 到处用方括号阻止分布。 先决定语义需要逐成员还是整体判断。
  7. 认为 never 是一个可返回的运行时值。 它表示没有成员，联合化简时会消失。
  8. 用模板字面量类型制造巨大组合。 大型或外部字符串集合更适合 string 加运行时校验。
  9. 认为精确类型会自动验证 JSON。 类型擦除后，外部输入仍是需要检查的 unknown。
  10. 重复实现内置工具类型。 Exclude、Extract、ReturnType 已能清楚表达时直接使用。

Learning Contract

进入 JavaScript / Node 执行模型前，你应当能够：

  • 手动计算简单条件类型的 true 与 false 分支。
  • 解释条件类型中的 extends 是可赋值判断，不是运行时继承。
  • 用 infer 从数组元素、函数返回值或对象属性中提取类型。
  • 逐步展开分布式条件类型，并说明 never 如何过滤联合成员。
  • 用方括号阻止分布，并预测整体判断结果。
  • 从字符串字面量联合计算模板字面量类型的组合。
  • 区分类型层字符串协议与运行时模板字符串创建。
  • 优先选择内置工具类型，并避免递归或巨大联合的过度设计。

Lab 12：从命令 kind 派生事件名

由你创建或修改：创建 src/lesson-12.ts，把本课案例、改写和 Lab 都保存在这里。

不要修改：tests/lessons.test.ts 与 scripts/；它们是课程验收工具。

你要交付什么

导出两个类型和一个泛型函数：

KindOf<T>
NoteEvent<T>
createNoteEvent<Kind extends string>(
  kind: Kind,
): `note:${Kind}`

类型规则

  1. KindOf<T> 匹配具有 readonly string kind 的对象，并用受 string 约束的 infer 提取 Kind；不匹配时得到 never。
  2. 输入是对象联合时，KindOf 必须分布并产生所有 kind 字面量的联合。
  3. NoteEvent<T> 把 KindOf 的每个成员转换成对应的 note:kind 字面量。
  4. createNoteEvent 的返回类型必须保留调用方传入的 Kind；传入 "add" 时结果类型是 "note:add"。

运行规则

  • 返回由普通模板字符串创建的 note:${kind}。
  • 接受任意 string，包括 "add"、"list"、"archive" 与自定义字符串。
  • 不要使用 any、unknown、类型断言、重载、分支、查找表或字符串替换。
  • Lab 保持普通函数导出，由课程 HTML 自动识别。

本课只证明编译期关系并创建一个字符串。第 13 课会把类型擦除、词法作用域、闭包与原型放回 JavaScript / Node 的真实执行过程。

三层提示

提示 1 · 先匹配 kind 属性

KindOf 的 extends 右侧写一个只含 readonly kind 的对象结构；在 kind 的类型位置使用 infer Kind extends string。

提示 2 · 把提取结果放进模板

NoteEvent 不需要第二个条件类型，直接把 KindOf<T> 插入 note: 模板字面量类型。

提示 3 · 运行时实现只有一个表达式

函数返回普通模板字符串 note:${kind}。TypeScript 7 能根据泛型 Kind 检查它与返回模板类型的关系。

折叠完整答案与逐行解析

显示完整答案 
export type KindOf<T> =
  T extends { readonly kind: infer Kind extends string }
    ? Kind
    : never;

export type NoteEvent<T> = `note:${KindOf<T>}`;

export function createNoteEvent<Kind extends string>(
  kind: Kind,
): `note:${Kind}` {
  return `note:${kind}`;
}
第 1–4 行
KindOf 让联合成员分别匹配 readonly kind；infer 提取受 string 约束的 Kind，不匹配成员变成 never。
第 6 行
NoteEvent 把提取出的每个 kind 字面量加上 note: 前缀；联合会自动展开。
第 8–10 行
泛型 Kind 保留输入字符串字面量，返回模板类型描述同一个 Kind 与输出的关系。
第 11 行
JavaScript 模板字符串创建真实返回值；没有断言、映射表或运行时类型对象。
第 12 行
函数结束；条件类型与 infer 在编译后均被擦除。
