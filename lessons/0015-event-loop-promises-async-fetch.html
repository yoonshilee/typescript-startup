等待一个结果，不等于堵住整个线程

Promise 表示未来的完成结果；await 暂停当前 async 函数，把继续执行安排到 Promise 反应任务中。Node 的事件循环可以在等待 I/O 时推进其他回调，但任何正在运行的 JavaScript 回调仍会执行到结束。

本课代码文件：创建 src/lesson-15.ts，异步案例仍写成导出的无参函数；runner 会 await 返回值；参数化 Lab 前添加 /** @lab */。

任务卡

完成物：实现 loadNoteTitles(ids, loadNote)，同时启动所有独立加载，用 Promise.all 等待，并按输入 id 顺序返回 title。

  • 区分同步调用栈、Promise reaction 微任务与计时器/I/O 回调。
  • 理解 async 函数总是返回 Promise，await 只暂停当前函数。
  • 判断任务之间是依赖顺序还是可并发关系。
  • 使用 Promise.all 保序聚合，并理解任一拒绝会让整体拒绝。
  • 用 fetch 读取 Response，区分网络失败与 HTTP 非成功状态。

前置回忆：第 13 课的同步调用会执行到返回

export function demoSynchronousOrder(): string[] {
  const trace = ["start"];
  trace.push("work");
  trace.push("end");
  return trace;
}

当前 JavaScript 调用栈不会被另一个普通回调从中间切开。异步 API 能登记未来工作，但当前同步片段仍先完成；事件循环随后才选择已就绪的后续任务。

详细心智模型：立即启动、保存 Promise、稍后继续

1. Promise 是一个普通运行时对象

export async function demoPromiseValue(): Promise<boolean> {
  const pending = Promise.resolve("Draft");
  return pending instanceof Promise;
}

创建 Promise 会立即得到对象；它可能处于 pending、fulfilled 或 rejected。状态只能向完成方向改变一次。Promise 不是线程，也不会让其中的同步计算自动并行。

2. async 函数每次调用都返回 Promise

export async function demoAsyncReturn(): Promise<string> {
  async function readTitle(): Promise<string> {
    return "Draft";
  }

  const titlePromise = readTitle();
  return titlePromise;
}

readTitle 中 return "Draft" 会完成返回的 Promise。外层 async 函数返回另一个 Promise，并采用 titlePromise 的最终状态；调用者必须 await 或显式处理 then/catch。

3. await 把当前函数拆成“之前”和“继续”

export async function demoAwaitSuspension(): Promise<string[]> {
  const trace = ["before"];
  const titlePromise = Promise.resolve("Draft");
  const title = await titlePromise;
  trace.push(`after:${title}`);
  return trace;
}

执行到 await 时，函数先返回 pending Promise；当 titlePromise fulfilled，后半段作为 Promise reaction 继续。即使等待已完成 Promise，继续部分也不会插回当前同步表达式中间。

4. 微任务在计时器回调前得到机会

export async function demoMicrotaskOrder(): Promise<string[]> {
  const trace = ["sync"];
  setTimeout(() => trace.push("timer"), 0);
  queueMicrotask(() => trace.push("microtask"));

  await new Promise<void>((resolve) => setTimeout(resolve, 0));
  trace.push("after-await");
  return trace;
}

本例得到 sync、microtask、timer、after-await。当前调用结束后先清空微任务；两个 timer 按登记顺序就绪，第二个 resolve 又安排 await 的继续。不要把这简化成“所有异步都按源码顺序”。

5. await 不会让 CPU 循环让出线程

export async function demoAwaitedValue(): Promise<number> {
  let total = 0;
  for (let value = 1; value <= 3; value += 1) {
    total += value;
  }

  return await Promise.resolve(total);
}

循环仍在事件循环线程同步完成；只有到 await Promise 时当前函数才暂停。给 CPU 密集循环外面套 async 不会自动放入 Worker，也不会提升并行度。

6. 独立操作要先全部调用，再一起等待

export async function demoConcurrentStart(): Promise<string[]> {
  const started: string[] = [];

  async function load(id: string): Promise<string> {
    started.push(id);
    return id.toUpperCase();
  }

  const pending = ["n1", "n2", "n3"].map((id) => load(id));
  const values = await Promise.all(pending);
  return [...started, ...values];
}

map 同步调用三次 load，先得到三个 Promise；Promise.all 再等待它们。这和在 for 循环里每轮立即 await 不同，后者要等前一个完成才启动下一个。

map 收集异步函数返回的 Promise

map 不会 await 回调，结果类型是 Promise<string>[]。要得到 string[] 必须交给 Promise.all；直接 await pending 只会得到原数组。

并发边界：先调用所有独立任务，再由一个 Promise 组合器拥有它们；需要前一步结果时才顺序 await。并发数量很大时应增加显式上限，而不是无界 Promise.all。

7. Promise.all 按输入位置排列结果

export async function demoPromiseAllOrder(): Promise<string[]> {
  const first = Promise.withResolvers<string>();
  const second = Promise.withResolvers<string>();
  const combined = Promise.all([first.promise, second.promise]);

  second.resolve("second");
  first.resolve("first");
  return combined;
}

第二个先完成，最终仍是 ["first", "second"]。Promise.all 的结果位置对应输入 iterable 的位置，不对应完成顺序；这正是 Lab 能保持 ids 顺序的原因。

8. 任一输入拒绝，Promise.all 的结果就拒绝

export async function demoPromiseAllRejection(): Promise<string> {
  const failure = new Error("load failed");

  try {
    await Promise.all([
      Promise.resolve("Draft"),
      Promise.reject(failure),
    ]);
    return "unreachable";
  } catch (error) {
    return error === failure ? "same error" : "other error";
  }
}

Promise.all 不会返回部分标题；它用首个观察到的拒绝原因拒绝。已经启动的其他操作不会自动取消，第 16 课会用 AbortSignal 建立显式取消协议。

9. 有依赖关系时才逐个 await

export async function demoSequentialDependency(): Promise<string> {
  async function findId(): Promise<string> {
    return "n1";
  }

  async function loadTitle(id: string): Promise<string> {
    return `${id}:Draft`;
  }

  const id = await findId();
  return loadTitle(id);
}

loadTitle 需要 findId 的结果，所以顺序等待是正确的。并发不是默认优化口号；先画数据依赖，再决定 Promise.all 还是逐步 await。

10. fetch 只负责传输，Response 还需要读取

export async function demoFetchText() {
  const response = await fetch("data:text/plain,Draft");
  return { ok: response.ok, status: response.status, text: await response.text() };
}

fetch 返回 Promise<Response>；Response 是状态、headers 与 body 流的容器。response.text() 再异步读取 body。Node 24 提供稳定的浏览器兼容 fetch，本例使用 data URL，不依赖外网。

一次请求同时观察状态与正文：本例得到 ok: true、status: 200、text: "Draft"。

HTTP 404 通常仍会 fulfilled

本例 data URL 返回成功，所以 ok 是 true。真实 HTTP 404/500 通常也会得到 Response，只是 ok 为 false；只有网络、协议或取消等失败使 fetch Promise 拒绝。调用方必须主动定义非成功状态策略。

补充观察与运行

示例 A：Promise.allSettled 保留每个最终状态

export async function demoAllSettled(): Promise<string[]> {
  const results = await Promise.allSettled([
    Promise.resolve("Draft"),
    Promise.reject(new Error("missing")),
  ]);

  return results.map((result) => result.status);
}

结果是 ["fulfilled", "rejected"]。只有业务确实需要所有结果时才选 allSettled；Lab 需要全部标题才能成功，所以使用 fail-fast 的 Promise.all。

示例 B：空 Promise.all 直接给出空结果

export async function demoEmptyPromiseAll(): Promise<number> {
  const values = await Promise.all([]);
  return values.length;
}

结果是 0，不会调用 loader，也不需要特殊分支。Lab 可以直接把空 ids 映射成空 Promise 数组。

示例 C：同步异常会变成 async 函数的拒绝

export async function demoAsyncThrow(): Promise<string> {
  async function fail(): Promise<never> {
    throw new Error("failed");
  }

  try {
    await fail();
    return "unreachable";
  } catch {
    return "rejected";
  }
}

async 函数体抛出的异常会拒绝返回 Promise；第 16 课会进一步约束 Error、Result 与失败传播。

常见误区

  1. 认为 Promise 就是一条后台线程。 它只表示最终完成状态。
  2. 认为 async 让同步 CPU 工作自动非阻塞。 函数仍同步运行到第一个真正等待点。
  3. 认为 await 阻塞整个 Node 线程。 它只暂停当前 async 函数的继续部分。
  4. 在循环中逐个 await 独立任务。 这会无意中串行化。
  5. 把函数本身传给 Promise.all。 要先调用函数，提供 Promise。
  6. 认为 Promise.all 按完成顺序返回。 它保持输入位置。
  7. 认为 Promise.all 拒绝会取消其他任务。 取消必须显式设计。
  8. 直接 await Array.map(async)。 数组不是 Promise，应 Promise.all。
  9. 只要 fetch fulfilled 就当作成功。 还要检查 response.ok 或 status。
  10. 启动 Promise 后不 await、不 return、也不 catch。 拒绝可能变成未处理失败。

Learning Contract

进入 Error、Result、AbortSignal 与失败传播前，你应当能够：

  • 按同步栈、微任务与计时器回调预测小程序的输出顺序。
  • 解释 async 返回 Promise 和 await 拆分继续执行的机制。
  • 识别同步 CPU 工作即使位于 async 函数中仍会阻塞。
  • 根据数据依赖选择顺序 await 或并发 Promise.all。
  • 说明 Promise.all 的输入保序、空输入与 fail-fast 行为。
  • 正确组合 Array.map(async ...) 的 Promise 数组。
  • 区分 fetch 传输完成、HTTP 状态与 body 读取。
  • 让每个启动的 Promise 都有明确的 await、return 或错误处理所有者。

Lab 15：并发加载笔记并保持输入顺序

你要交付什么

type LoadedNote = {
  readonly id: string;
  title: string;
};

type NoteLoader =
  (id: string) => Promise<LoadedNote>;

loadNoteTitles(
  ids: readonly string[],
  loadNote: NoteLoader,
): Promise<string[]>

运行规则

  1. 立即按 ids 顺序调用每个 loadNote，不要等待前一个完成后才启动后一个。
  2. 用 Promise.all 等待全部 LoadedNote。
  3. 按 ids 对应的原顺序返回 title，即使 Promise 以不同顺序完成。
  4. ids 为空时返回空数组且不调用 loader。
  5. 任一 loader 拒绝时，让返回 Promise 使用同一原因拒绝。

实现限制

  • 使用 async/await、map 与 Promise.all。
  • 不要使用 for/for...of/while、串行 await、计时器、fetch、catch、allSettled、race、any、unknown 或类型断言。
  • 不要排序结果，也不要按完成顺序 push。
  • Lab 函数前保留 /** @lab */。

loader 是注入的异步边界，因此测试能精确控制完成顺序而不访问网络。第 16 课会在这个边界上加入 Error、Result 与 AbortSignal。

三层提示

提示 1 · 先得到所有 Promise

对 ids 执行 ids.map(loadNote)。map 在当前同步片段中调用所有 loader，得到 Promise 数组。

提示 2 · 一次等待全部结果

const notes = await Promise.all(...)；notes 的位置与 ids 一致，不用自己恢复顺序。

提示 3 · 最后只投影 title

对 fulfilled 后的 notes 做一次同步 map，返回每个 note.title。

折叠完整答案与逐行解析

显示完整答案 
export type LoadedNote = {
  readonly id: string;
  title: string;
};

export type NoteLoader =
  (id: string) => Promise<LoadedNote>;

/** @lab */
export async function loadNoteTitles(
  ids: readonly string[],
  loadNote: NoteLoader,
): Promise<string[]> {
  const notes = await Promise.all(ids.map(loadNote));
  return notes.map((note) => note.title);
}
第 1–4 行
LoadedNote 描述异步边界完成后提供的数据；id 对消费者只读。
第 6–7 行
NoteLoader 把一个 string id 映射为未来的 LoadedNote。
第 9 行
@lab 让自动 runner 不调用需要 ids 与 loader 的函数。
第 10–13 行
async 函数公开 Promise<string[]>，同时接受 readonly ids。
第 14 行
map 立即启动所有 loader；Promise.all 等待并按输入位置生成 notes，拒绝则原样传播。
第 15 行
所有数据就绪后同步提取 title；空 notes 自然得到空数组。
第 16 行
函数结束；没有串行循环、排序、计时或网络依赖。
